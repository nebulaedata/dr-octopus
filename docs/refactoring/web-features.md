## 验证结果

- 单元与结构测试：223 项全部通过，新增 feature 目录和依赖图约束。
- lint：通过，`i18next-cli extract --ci` 确认语言目录无需更新。
- 类型检查：`tsc -b --pretty false` 通过；生产构建通过。
- 最终聚焦浏览器回归：37 项全部通过，包含公开惰性入口、Composer 焦点/快捷键、首次发送与恢复、草稿、语言切换，以及 1280/390/320px 下的模型能力编辑。
- 首次入口统一曾引起提前加载，已通过 feature 内惰性包装与路由接线修正。最终首页同步 JS 依赖闭包为 2,503,867 字节，基线为 2,507,895 字节；这是未压缩文件体积之和，不是网络压缩流量。新增浏览器用例确认首页不请求会话页面实现，进入 Session 后才加载。
- Jev 页面在相同 mock、英语、浅色、1280×1000 视口下进行前后截图对照，像素差异为 0；两个版本均无页面异常。该结果只证明这个已检查场景，不代表全部界面逐像素验证。

## 未通过的既有浏览器用例

浏览器全套不能报告为通过。9 个既有测试文件的一次综合运行为 56 项：44 通过、11 失败、1 因超时取消；另跑的知识批量操作用例失败。上述 **12 个失败及 1 个取消** 均在从基线 Git 版本提取并独立构建的旧前端上复现相同失败点：

- Jev 记忆筛选：测试查找旧开关文案，实际界面已是“开启 Jev 前置判断”。
- Server 设置：两个用例仍查找旧的重启按钮名称。
- Session interruption：后台任务、停止、错误和子代理用例使用与当前展示不一致的定位；其中无效后台状态用例超时取消。
- 知识批量操作：测试查找中文 checkbox 名称，而现有 ARIA 使用 `Select document ...`。

本轮未修改这些断言或产品文案来消除失败；未覆盖到的后续交互不能据此宣称通过。稳定通过的浏览器集合在最终加载修正后另行重跑，得到上述 37 项通过结果。测试文件数量与通过数量不是新增业务能力的度量。

## 保持的契约

- API、路由、URL 搜索状态、查询键、缓存失效与持久化键不变。
- Jev 密钥仍不进入 Query mutation 缓存，独立修订与模型草稿行为不变。
- 既有 realtime、SSE、QueryClient、Zustand、上传任务 Map 的实例所有权保持不变；不新增轮询、兼容层或双实现。
- 工具选择顺序、原始错误输出、历史与实时投影保持不变；没有为测试暴露生产 resolver。
