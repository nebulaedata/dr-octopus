## 新组件契约

从 `@octopus/custom-ui/components/alert` 导入 `Alert`，以及 `AlertProps`、`AlertVariant` 类型。固定结构完全由组件内部维护，不接受 `children`，不导出供调用方组合布局的子组件。

| 参数          | 含义                                                        | 默认值            |
| ------------- | ----------------------------------------------------------- | ----------------- |
| `variant`     | `success / info / warning / danger`，决定主题颜色与默认图标 | `info`            |
| `title`       | 可选标题                                                    | 无                |
| `description` | 必填正文，支持 ReactNode                                    | 必填              |
| `showIcon`    | 显示左侧状态图标                                            | `false`           |
| `icon`        | 自定义图标，配合 showIcon 使用                              | 根据 variant 选择 |
| `details`     | 正文下方的详情内容，例如可展开的诊断                        | 无                |
| `action`      | 详情下方的操作内容；组件内部负责右对齐与换行                | 无                |
| `allowClose`  | 显示关闭按钮，只隐藏当前挂载实例                            | `false`           |
| `onClose`     | 手动关闭请求时通知宿主，不承担保存、计时、重试或通知移除    | 无                |
| `role`        | 默认 danger 为 alert，其余状态为 status；可显式覆盖紧急程度 | 按 variant 推导   |
| `closeLabel`  | 关闭按钮的可访问文案，可本地化                              | `Close alert`     |

图标拥有独立固定位置，标题、正文、详情和操作共享可收缩内容列，长文本自动换行；关闭按钮独立预留空间。调用方传入内容与业务控件，组件负责排列。variant 或内容更新不会恢复已关闭实例；新通知需要更换 key 或重新挂载，不写入持久存储。原生 div 属性、ref 与 role 可透传；HTML title 由组件的标题参数替代，不接受 dangerouslySetInnerHTML。

`success` 使用共享 `--success` 成功色与圆形勾选图标；标题与正文使用常规 text-foreground，只有图标使用 text-success；参考 Ant Design 的状态色分工，不修改共享 token；`info` 使用现有中性主题色。业务确认、成功提示、自动消失及业务关闭回调仍需逐项评估；本地关闭不能替代业务流程。后续接入检查消费方 Tailwind 扫描 `packages/custom-ui/src`。

`A010` 已接入固定结构：description 传入错误文案，showIcon 启用 danger 图标，details 传入 WorkflowDiagnosticDetails，action 直接传入修复 Button。

```tsx
import { Alert } from '@octopus/custom-ui/components/alert';

<Alert variant="warning" showIcon description="请检查配置后重试。" allowClose closeLabel="关闭提示" />;
```

## 适用范围与生命周期边界

Alert 负责固定结构、颜色、图标、阅读顺序与本地关闭，适用于行内提示和通知表面；调用方仍负责决定提示是否紧急、是否允许关闭，以及业务动作。组件不提供悬浮位置、自动消失、通知队列或业务重试。

默认 danger 使用 `role="alert"`，success/info/warning 使用 `role="status"`。这是本组件的默认策略；紧急警告可以显式传 role="alert"，不需中断的错误可以显式传 role="status"。视觉状态与业务紧急程度不强绑定。

手动关闭会隐藏当前实例并调用 onClose；自动消失由宿主移除通知，不触发组件的手动关闭回调。新通知使用新的 key，避免继承已关闭状态。关闭只影响展示，不表示错误已修复或业务操作已取消。

SettingsToast 保持顶部悬浮位置；成功提示空闲 4 秒后关闭，鼠标停留或键盘焦点位于通知内时不关闭，离开后重新计时 4 秒；错误提示不自动关闭。SettingsToast 负责计时清理、通知 ID 和宿主 close 回调，公共 Alert 负责内部布局与手动关闭入口。

本次实测：原 text-success 小字号正文在浅色主题仅 3.00:1；第一轮混色方案曾测得默认浅色 6.47:1、深色 9.88:1；用户随后要求参考 Ant Design，现改为常规文字色与绿色图标，第一轮数值仅保留为历史证据。该结论覆盖当前仓库默认主题，新增主题仍需验证。

### 状态核定规则与审批范围

本表的 variant 由代理阅读实际渲染条件、文案来源及业务结果后核定，不要求用户判断业务语义。单处覆盖多种状态时，列出明确条件映射；success 表示已完成，info 表示说明/进行中/无异常取消，warning 表示风险、降级、待核实结果或需要注意的约束，danger 表示确定失败或当前能力不可用。不可恢复的删除/覆盖确认属于 warning，动作按钮仍可使用 destructive。

“确认状态”记录替换结果或保留理由。用户已批准全部应用替换；N/C 候选按实际布局与语义核查后处理。涉及未知结果、授权、删除与凭据展示的提示不能通过关闭或换色改变业务边界。

A122 已改为由各消息产生分支携带 variant 与 text，保存、覆盖、冲突、结果未知、刷新分别映射状态。A041 的运行结果摘要按实际 status 细分，不再沿用 failed 布尔值把 needs_attention 一律视为错误。普通说明保留既有 note 语义；具有多个终态的提示不要从翻译后的文字推断状态。
