# Browser Host 生命周期验证计划

决策：[ADR-0090](../adr/0090-browser-host-lifecycle.md)。

2026-11-03 从 ADR-0090 迁入 2026-11-02 的验收计划，并按用户确认的新协议单线实施要求修订。原验收矩阵继续作为发行门禁；本轮实现与实际验证追加在下方，不将局部通过提升为完整发行验收。

以下为发行阻断验收，使用隔离 Windows 用户/Profile/测试 Host，保留真实打包产物证据。单元测试不能替代浏览器真实启动 Native Host。

| 场景                                                | 必须结果                                             |
| --------------------------------------------------- | ---------------------------------------------------- |
| 新用户安装，Chrome/Edge 首次连接                    | 无手工命令，真实 nonce 往返，权限仍需原有显式启用    |
| 正式版与 dev 同时运行、反复启动/停止/重建           | 注册、数据、Profile、连接互不影响                    |
| 更新后删除旧下载/安装目录，清理 dev dist            | 当前入口和 Host 仍可用                               |
| 新协议下扩展与 Executor 分别升级、协议不一致        | 同协议自动连接；不一致指出具体更新目标，无旧协议降级 |
| 写文件/写第一项注册/发布后进程崩溃、断电模拟        | 下次恢复为一致状态，有明确 journal，无混合组件       |
| 第二个浏览器注册失败、磁盘不足、文件被占用          | 分项结果准确，旧可用状态保留或恢复，不冒称全部成功   |
| 多个更新进程、旧进程启动、旧卸载器运行              | 只有当前所有者推进 generation，不倒退抢占            |
| 删除已知自有注册或破坏受管包                        | 自动恢复并重新验证                                   |
| 未知注册与旧 manifest 消失                          | 无盲目覆盖，确认修复后可恢复且保留备份               |
| Host/Runtime 崩溃、Worker 回收、浏览器重启/休眠恢复 | 有界恢复，真实状态一致，用户暂停保持                 |
| 点击/输入发送后断线、旧回复迟到                     | 不重放副作用，不污染新连接，未知结果保留             |
| 浏览器关闭、禁用扩展、撤销网站权限、策略禁止 Host   | 正确分层，不误判成功、不无限修复注册                 |
| 新包失败，旧包可用/已不兼容分别测试                 | 前者回退，后者明确待修复；不回滚用户数据             |

暂定验收目标：Executor 与已启用扩展均可运行时，正常安装/升级无需修复按钮；短暂进程故障在首次不超过 60 秒的恢复窗口内完成重连；持续失败后进入上限 5 分钟的低频探测，不将该阶段描述为 60 秒恢复保证，计时排除浏览器关闭/休眠，实际 alarm 调度偏差单独记录。单次本地修复有 60 秒截止，超时必须收束并报告，不能挂起界面。目标需实测，当前不视为已达成。

## 连接与业务边界回归

- 连接模块抽取前后，已有桥接与 popup 测试保持通过。
- 录制与本地技能在 Executor 离线时继续可用，模型和 Agent 业务不依赖新维护服务。
- SkillFileClient 断线清理、重连新会话、迟到回包和旧 post 拒绝均有覆盖。
- 当前工作区 dev 与正式实例同时运行，注册、端口、Profile 和业务数据不交叉。用户已取消双 worktree 并行开发要求。
- 集成从同一提交构建两端，验证真实 Native Host 往返和动作断线不重放。

### 首次失败与修正

保留首次日志，不以成功重跑覆盖：

- 扩展抽取初跑 7/8：旧夹具只保留一个 onInstalled 监听器，改成真正的多监听器事件后通过。
- 协议切换初跑发现成功场景仍硬编码 v4；更新到当前协议，并增加实际 Worker 内嵌 ID 与构建记录一致性验证。
- 安装脚本在当前环境中无法自动找到 Get-FileHash，已显式导入系统 Utility 模块。
- Executor 全量初跑为 303 项、299 通过、3 失败、1 取消：两个旧脚本契约测试已重写为新维护契约；维护测试将已加载的临时 DLL 留在自身进程，清理重试导致超时。改用独立子进程持有该 DLL，相关 50 项重新通过。未把这次全量初跑写成全量通过，也未重复与连接无关的 2 GiB 等测试。
- GUI 初跑达到 120 秒总期限；阶段记录定位在 Electron 启动。规范化 Windows 应用目录，去掉末尾反斜杠，并给启动/动作设置明确期限、显示测试窗口后，原总期限内复验通过。
- 第一张成功链路截图采于 Executor 在后台、UI 尚未刷新时；随后切回所属窗口并等待界面真实更新，另存 connection-live-verified.png，不覆盖先前截图。
- 一项失败测试临时目录清理被自动审批策略拒绝，未给出具体原因；保留该残留，后续独立测试目录均按各自夹具清理。
