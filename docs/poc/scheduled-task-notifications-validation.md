## 实施状态与验收

已实施 Server 通知表、版本回执、通知查询、普通会话结算通知，以及 Web 通知弹窗与会话蓝点。经用户确认，Agent 新增仅控制凭据可访问的 `run-result` 查询；Server 登记真实执行会话，提供只读分页结果，来源会话和执行历史均可跳转。

后台首次延迟 1 秒开始，每轮结束后间隔 5 秒：每个工作区检查最新 50 条，另用每轮 50 条的游标补齐旧历史。导入与通知提交在同一事务中完成，运行 ID 去重。结果查看不申请 Runtime；后端拒绝执行、激活、Runtime 订阅、派生及直接删除执行文件。会话列表中可以移除结果入口，去重凭据继续保留，运行历史依然保留原始执行记录。

归档任务在普通 `get` 中被隐藏，因此清理必须使用 `run-result` 并只接受 `SCHEDULE_RUN_NOT_FOUND` 作为永久删除证据。网络错误、文件暂不可读、归档均不得触发清理。通过 Server 彻底删除后立即清理；其他 Host 删除则由分页校验补偿。报告文件位于 Server `state/scheduler-reports`；底层执行文件始终由 Agent 管理。缺失文件返回明确的缺失报告，不推断任务未执行。

新增隔离回归覆盖：控制凭据与工作区隔离、活动运行拒绝导出、路径越界拒绝、缺失文件降级、成功与执行前拦截、并发重复导入、重启去重、自动补齐、读取版本竞争、只读访问不分配 Runtime、归档保留及永久删除清理。浏览器使用保留的历史结果验证通知、蓝点、结果显示和已读回执，没有重跑已有任务。

本轮交付为应用内通知；Server 离线期间先由 Scheduler 保留结果，Server 恢复后补齐。系统桌面推送、邮件及外部消息通道不在本轮范围内。图片消息在此只读视图中显示保留说明，原始内容仍保存在 Pi 执行文件中。
