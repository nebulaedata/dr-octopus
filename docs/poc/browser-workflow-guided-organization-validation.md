## 10. 验收与实施顺序

1. 2026-10-31用户已选择实际显示第2稿（证据优先）为视觉方向；未授权实施。
2. 已补齐第2方向的两张v2状态板：深色、长内容/补充说明、短窗口、待回答回访、失败恢复、最终预览；用户已明确确认，登记为approved；等待实施指令。
3. 用户明确实施后：先实现当前契约与领域回归，再持久化/Host生命周期，再接入已批准界面。
4. shared构建成功后构建扩展双目标；聚焦测试再运行应用test/lint/typecheck，随后隔离Chrome/Edge受控集成。
5. 真实提供商测试另列合成场景和次数申请，不能使用之前已经耗尽的30+12次额度。

必要回归：零问题直接产出；一/多问题；暂缓不反复追问；选项点击不发模型请求；答案ACK前后关闭Popup；双Popup冲突/重复提交；Worker重启等待恢复；Host预期退出/异常关闭；更换模型/撤销授权；在途取消与迟到结果；预算耗尽；用户回答不得生成额外点击/导出/付款；未知条件保存草稿；manual不能自动成功；旧审批不能覆盖新结果；历史投影写失败不产生重复草稿；360×600及短窗口、键盘与深浅色。
