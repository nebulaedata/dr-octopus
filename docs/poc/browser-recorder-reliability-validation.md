# 自研录制器：单层同源 iframe 验收计划

> 2026-11-03：计划已按最小增量范围修订；新增用例全部未执行。原计划没有运行证据，本次没有删除或改写任何实测结论。
>
> 契约见[开发设计](../architecture/browser-recorder-reliability.md)，决定见 [ADR-0092](../adr/0092-browser-recorder-reliability.md)。执行层保持 PageController，不以本轮录制验收证明重放能力。

## 1. 基线与环境

此前静态检查确认：顶层 allFrames 为 false、只准入 frameId 0、文档/批次按 Tab 管理，已有 ACK、脱敏和三秒停止收尾。相关旧测试本次未重跑；新增能力运行证据：none yet。

使用 Windows 独立 Profile、合成页面和扩展副本，分别记录 Chrome Stable／Edge Stable 实际版本、构建身份、步骤、期望、实际结果和证据路径。纯存储测试可共享；涉及浏览器 API、注入和生命周期的用例两种浏览器分别执行。保留首次失败及复测结果，不操作日常 Profile 或真实账号。

## 2. 必需验收

以下均为“未执行”。沿用已有测试覆盖顶层事件语义，只新增多文档变化所需回归。

| ID  | 场景                                                         | 通过依据                                                             |
| --- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| R01 | 顶层与两个同源 iframe 操作同名控件                           | 各文档记录一次；目标和编辑引用不混淆；只有顶层浮条                   |
| R02 | 开始前已有/开始后新增 iframe，枚举和注入时导航               | 当前文档通过握手才采集；旧目标不误注入、重复发现不重复监听           |
| R03 | frame 刷新、删除、重新插入、顶层导航                         | 登记和监听正确更新；旧消息不能覆盖新文档；未知尾部提示缺口           |
| R04 | 跨域、嵌套、about:blank/srcdoc、opaque sandbox、超过文档限额 | 拒绝采集并提示范围；不保存未获准文档正文                             |
| R05 | 错误窗口/非参与 Tab、错误文档、旧 epoch、子文档管理命令      | 拒绝且不写事实或游标，不扩大授权                                     |
| R06 | 两文档批次交错、ACK 丢失重发、跳批、事务失败                 | 逐文档游标独立；重复不增事实/计数；失败无半批次、不误 ACK            |
| R07 | 暂停/停止时有合并输入，一个文档失联，期间新 hello 或迟到批次 | 全部登记文档并行收尾；沿用三秒超时；未确认有提示，终态不复活         |
| R08 | 显式恢复、BFCache、Worker 重建/浏览器重启                    | 批次基线一致；无重复监听和引用串用；异常不自动续录                   |
| R09 | 子文档 IME/选择/敏感字段；现有顶层录制回归                   | 复用既有语义，消息/DB/日志/证据中无敏感合成哨兵；不新增重复步骤      |
| R10 | 不同 frame 的同名目标及相同脱敏 URL；旧录制读取              | 不跨文档误合并或强行归因；旧事实/gaps 保留，模型不获运行时 ID        |
| R11 | 全支持/含未支持 frame、注入失败、保存未确认                  | 不再因任意 iframe 报警；范围与保存失败文案准确，历史提示保留         |
| R12 | Executor 离线、Bridge 暂停、录制与执行冲突、连续导航后停止   | 录制独立可用；准入不变；无 Controller 初始化、残留监听或持续增长登记 |

## 3. 检查与完成条件

开发按应用规范先构建 shared 和 Chrome/Edge 扩展，再执行 focused tests、lint、typecheck 及相关现有录制回归。实现后登记实际新增测试文件与命令，不把尚不存在的命令写成可执行步骤。

性能只针对变化做检查：在相同环境比较顶层基线与多 frame 场景，记录握手/ACK 延迟、停止耗时和资源回收，确认无明显输入卡顿、无限重试或重复监听。有可复现退化再补专项数据；不新增无基线的 p95 指标门禁、全量压测工程或包体目标。

R01–R12、相关既有录制回归与 Chrome/Edge 真实安装行为均通过后，才能宣称本轮支持交付。Chromium 或 Desktop Chrome 设备参数不替代 Edge 验证；侧载与商店安装验收分开记录。

若实际需要升库，补测旧数据/索引保留与 blocked 升级；只增会话字段则不人为创建升库任务。实施后在[Executor 验证总表](executor-validation.md)关联本专题，并记录命令、范围、失败及证据。

跨域、多层嵌套、新事件语义、覆盖时间轴、独立回执库和执行层验证均不构成本轮完成条件。
