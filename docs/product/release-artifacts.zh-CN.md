# Dr.Octopus 发布产物总览

**简体中文** · [English](./release-artifacts.md)

本页说明一次仓库 Release 会产生什么、在哪里获取，以及哪些步骤需要人工执行。具体安装、发布和失败恢复操作以各产品的现行手册为准；表中的“自动”均以对应流水线成功为前提。

在仓库根目录运行 `pnpm release:publish`，选择发布下一版本并确认后，脚本先更新 Dr.Octopus 与 Executor 的独立版本、提交并推送版本 Tag，再构建并发布 npm 包，最后创建同 Tag 的 GitHub Release。Release 的 `published` 事件同时启动 Docker 和 Executor 两条 GitHub Actions 工作流。它们异步完成，新 Release 刚出现时不代表所有附件已就绪。

| 产物                              | 发布方式与时机                                                                                                      | 获取位置                                                                                                                                                                        | 使用范围与前提                                                                                                                                                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dr-octopus` npm 包               | 本地 `pnpm release:publish` 构建并发布；成功后才创建 GitHub Release。                                               | [npm](https://www.npmjs.com/package/dr-octopus)；`npm install -g dr-octopus`。                                                                                                  | 在本机直接运行 CLI、TUI 或 Gateway，无需 Docker。需要 Node.js 22.19+；首次运行还需安装运行依赖（可执行 `dr-octopus deps install`），启动 Gateway 后才能使用 Web 界面，并需配置模型凭据。见[中文安装说明](../../README.zh-CN.md#安装)。 |
| Docker Hub 镜像                   | GitHub Release 发布后，由 `Docker release` 工作流等待对应 npm 包可下载，再构建、测试并推送。                        | [`docker.io/nebulaedata01/dr-octopus`](https://hub.docker.com/r/nebulaedata01/dr-octopus)。                                                                                     | 当前成品镜像面向 Linux AMD64；部署还需要 Docker Engine 与 Compose。见[Docker 安装说明](../../README.zh-CN.md#docker-安装)。                                                                                                            |
| Docker 安装 ZIP                   | 同一 Docker 工作流验证镜像后，上传到对应 GitHub Release。                                                           | [GitHub Releases](https://github.com/nebulaedata/dr-octopus/releases) 的 `dr-octopus-docker-<镜像标签>.zip`。                                                                   | 包含固定镜像版本的 Compose 配置；它不是镜像本身，也不是 GitHub 自动生成的源码 ZIP。等待附件实际出现后再下载。                                                                                                                          |
| Windows Executor 安装版与免安装版 | GitHub Release 发布后，由 `Executor Windows unsigned delivery` 工作流构建、测试并验收，通过后上传附件。             | 同一 [GitHub Release](https://github.com/nebulaedata/dr-octopus/releases) 中的 `Dr.Octopus-Executor-<Executor版本>-win-x64-setup-unsigned.exe` 和 `...-unpacked-unsigned.zip`。 | Windows x64 **未签名验收产物**，不是已完成签名与干净机器验收的正式发行包。浏览器扩展随 Executor 产品树提供，按[本地安装说明](../../apps/executor/INSTALLATION.md#chrome--edge-本地安装)加载；此流程不会自动上架 Chrome 或 Edge 商店。  |
| Harbor 镜像                       | **人工同步**：等 Docker Hub 对应标签发布成功后，在可访问 Docker Hub 和内部 Harbor 的机器上运行 `pnpm docker:sync`。 | `harbor.n.nebulaedata.com/nebulae/dr-octopus`；默认预填本地发布配置版本和 `latest`，以英文逗号分隔；支持填写多个标签并自动去重。版本与 `latest` 同选时，核对内容一致后指向同一版本摘要。                                                                                          | 内部分发副本；不是 GitHub Release 自动产物。执行机器需要 Docker CLI、Buildx、Harbor 推送权限及到两个镜像仓库的网络连通性；是否需要代理取决于实际网络。见[Harbor 同步手册](../../deploy/docker/HARBOR.md)。                             |

核对一次发布时，分别查看 npm 精确版本、[Docker release 与 Executor Actions](https://github.com/nebulaedata/dr-octopus/actions) 的结果，以及 GitHub Release 的实际附件。Harbor 还需核对同步命令返回的目标摘要。某一路失败时，仅该路产物未就绪；不要把创建了 GitHub Release 视为所有交付完成。

维护者发布命令、凭据和失败恢复见 [CLI 联合发布指南](../../apps/cli/README.md#npm-与-github-联合发布)；Docker 与 Executor 的详细门禁分别见 [Docker 工作流说明](../../.github/workflows/README.md)和 [Executor 交付指南](../architecture/executor-delivery.md#github-release-assets-与-web-下载地址)。浏览器商店发布是独立流程，见[扩展发布手册](../../apps/browser-extension/RELEASE.md)。
