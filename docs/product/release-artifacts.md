# Dr.Octopus release artifacts

[简体中文](./release-artifacts.zh-CN.md) · **English**

This page summarizes what a repository release produces, where to find each artifact, and which steps require a maintainer. The linked product guides remain the source for installation, publication, and recovery procedures. An automatic artifact is available only after its workflow succeeds.

From the repository root, `pnpm release:publish` prompts for a new release, updates the independent Dr.Octopus and Executor versions, commits and pushes the version tag, builds and publishes the npm package, then creates the matching GitHub Release. Its `published` event starts the Docker and Executor GitHub Actions workflows in parallel. They finish asynchronously, so a new Release may initially have no packaged downloads.

| Artifact                                    | Publication and timing                                                                                                                                                | Where to get it                                                                                                                                                                     | Scope and prerequisites                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dr-octopus` npm package                    | Built and published by local `pnpm release:publish`; the GitHub Release is created afterward.                                                                         | [npm](https://www.npmjs.com/package/dr-octopus); `npm install -g dr-octopus`.                                                                                                       | Runs the CLI, TUI, or Gateway directly on the host without Docker. Requires Node.js 22.19+ and runtime dependency installation on first use (`dr-octopus deps install` is available). Start the Gateway to use the Web UI, and configure model credentials. See [installation](../../README.md#installation).                                              |
| Docker Hub image                            | After the GitHub Release is published, the `Docker release` workflow waits for the exact npm package, then builds, tests, and pushes the image.                       | [`docker.io/nebulaedata01/dr-octopus`](https://hub.docker.com/r/nebulaedata01/dr-octopus).                                                                                          | The current image targets Linux AMD64. Deployment also requires Docker Engine and Compose. See [Docker installation](../../README.md#docker-installation).                                                                                                                                                                                                 |
| Docker installation ZIP                     | The same Docker workflow uploads it to the matching GitHub Release after verifying the image.                                                                         | [GitHub Releases](https://github.com/nebulaedata/dr-octopus/releases): `dr-octopus-docker-<image-tag>.zip`.                                                                         | Contains Compose configuration pinned to an image version. It is neither the image itself nor GitHub's autogenerated source ZIP. Wait for the asset to appear before downloading it.                                                                                                                                                                       |
| Windows Executor installer and portable ZIP | After the GitHub Release is published, `Executor Windows unsigned delivery` builds, tests, and checks the Windows package, then uploads both assets.                  | The same [GitHub Release](https://github.com/nebulaedata/dr-octopus/releases): `Dr.Octopus-Executor-<executor-version>-win-x64-setup-unsigned.exe` and `...-unpacked-unsigned.zip`. | **Unsigned Windows x64 acceptance artifacts**, not a signed release with clean-machine acceptance complete. Browser extensions are included in the Executor product tree and loaded following the [local installation guide](../../apps/executor/INSTALLATION.md#chrome--edge-本地安装). This workflow does not publish them to the Chrome or Edge stores. |
| Harbor image                                | **Manual sync:** after the corresponding Docker Hub tag is available, run `pnpm docker:sync` on a machine that can reach Docker Hub and the internal Harbor registry. | `harbor.n.nebulaedata.com/nebulae/dr-octopus`; the default is `latest`, and an exact version requires an explicit tag.                                                              | An internal distribution copy, not an automatic GitHub Release artifact. The sync host needs Docker CLI, Buildx, Harbor push access, and network access to both registries. Whether a proxy is required depends on that network. See the [Harbor sync guide](../../deploy/docker/HARBOR.md).                                                               |

To verify a release, check the exact npm version, the [Docker and Executor Actions](https://github.com/nebulaedata/dr-octopus/actions), and the assets actually attached to the GitHub Release. For Harbor, also check the destination digest reported by the sync command. A failed workflow leaves its artifact unavailable; creating a GitHub Release alone does not complete every delivery.

Maintainer commands, credentials, and recovery are covered by the [CLI publication guide](../../apps/cli/README.md#npm-与-github-联合发布). Detailed gates are in the [Docker workflow guide](../../.github/workflows/README.md) and [Executor delivery guide](../architecture/executor-delivery.md#github-release-assets-与-web-下载地址). Browser store publication is a separate process described in the [extension release guide](../../apps/browser-extension/RELEASE.md).
