# Dr.Octopus 中文产品与宣传素材库

整理日期：2026-10-27。整理者：Codex。

产品宣传主线：**数据不出域，模型与算力部署在单位内部。** 基于 DGX Spark 独立部署，将模型推理、算力与 Dr.Octopus 智能体平台集成在一个小盒子里，面向政府、国企、公共事业单位及有数据保密要求的企业。用户通过域内浏览器工作台使用 AI，内部资料在单位指定的数据域内处理。

后续采用多租户管理，每个租户使用独立镜像部署独立运行实例，分别隔离数据与持久化存储。这是用户确认的产品与交付方向，不表示当前代码已经完成 DGX Spark 整机适配、全链路不出域验证、多租户管理或隔离验收。下文的 Windows 本地执行器指连接用户设备的执行组件，与 DGX Spark 上的智能体平台分工协作。

本文面向官网、产品介绍、社交媒体、演示脚本和推广选题。依据当前工作区的 README、功能实现、架构文档与验收记录整理，不代表所有功能已经进入同一个公开安装包，也不代表已完成所有平台和真实业务场景的验收。

功能介绍与应用设想分开理解：功能介绍描述已有能力；场景示例描述这些能力可以怎样组合使用，未逐一进行真实业务验证。面向数据不出域交付，对话、向量检索、重排、OCR 等实际启用的数据处理链路应使用盒内或单位批准的域内服务。通用软件中支持的外部模型、云端图像、云端语音、联网检索与外部 MCP 不自动纳入该交付范围；缺少合适域内实现的功能应不启用，不以外部服务自动替代。

## 一、产品定位：Dr.Octopus 是什么

### 1. 一句话介绍

Dr.Octopus 是一款面向政企数据保密需求的 AI 智能体一体机，基于 DGX Spark 将模型、算力与智能体平台部署在单位内部，让资料分析、知识问答与任务执行在指定数据域内完成。

### 2. 面向普通用户的介绍

你可以把 Dr.Octopus 理解为一个部署在单位内部的 AI 小盒子：算力在内部，模型在内部，智能体也在内部。工作人员通过域内浏览器访问工作台，在无需向公共云 AI 上传内部材料的交付方案中，开展资料整理、知识查询和任务处理。

把项目文件放进工作区，把常用资料整理进知识库，再用自然语言说明目标，AI 就能结合可用工具查找信息、分析文档、编写内容、处理文件和执行命令。需要持续开展的工作，可以设置为定时任务；适合长期保留的偏好与事实，可以整理进记忆。

配合 Windows 本地执行器与浏览器扩展，还可以让具备相应能力的智能体在授权范围内操作本机文件、网页和桌面界面。

### 3. 面向专业用户的介绍

Dr.Octopus 软件基于 Pi 智能体运行与扩展生态，通过工作区、多会话、模型服务配置、Skills、MCP、权限策略和后台任务管理，将模型能力接入项目与业务工作环境。产品以 DGX Spark 为独立部署载体，集成算力与智能体平台，以 Web 为最终用户主要入口，保留 TUI 作为专业使用入口。

核心客户是政府、国企、公共事业单位及有数据保密要求的企业：既希望使用 AI 提高工作效率，又要求内部材料、提问内容与处理结果留在指定数据域内。后续在一体机内采用多租户管理，为每个租户通过独立镜像部署独立实例，隔离各自数据；不代表每个租户独占一台物理设备。

### 4. 产品关键词

数据不出域、模型域内部署、算力域内部署、政企 AI、内部资料处理、DGX Spark、AI 智能体一体机、软硬一体交付、独立部署、域内浏览器工作台、多租户管理（后续方向）、租户独立实例（后续方向）、数据隔离（后续方向）、项目工作区、知识库、长期记忆、定时执行、Skills、MCP、权限可控。

### 5. 品牌联想

“Octopus”可以承接章鱼多触手的品牌表达：一个目标，连接文件、资料、工具、浏览器与电脑等多个工作触点。

适合使用的比喻是“连接工作环节”“把工具组织起来”“让任务有更多执行触点”。不要由此延伸成“无限智能体”“任意工具都能用”或“所有流程都能全自动完成”。

## 二、最值得传播的核心价值

### 首要价值：数据不出域，AI 围绕内部材料开展工作

政府、国企、公共事业单位和企业往往持有大量不宜上传公共云的内部资料。产品的核心交付方向是在单位内部部署模型推理、算力与智能体平台，使资料导入、问题处理、知识检索及结果保存留在指定数据域内，减少为使用 AI 而向外部服务传递内部数据的需求。

宣传表达：**数据不出域，模型与算力就在单位内部。**

价值解释：内部制度、项目材料、经营数据和业务文档，可以在域内用于知识问答、内容整理及任务辅助，让数据保护要求与 AI 应用需求在同一套部署方案中落地。

交付口径：这里的“域”由客户的网络、系统与管理边界定义，不简单等同于一台设备。正式承诺应覆盖实际启用的数据处理服务、工具、日志、备份与运维通道，并以配置和验收结果为准；不凭设备独立部署直接宣称已经实现全链路不出域。

### 算力与智能体集成，一台设备承载 AI 工作环境

产品以 DGX Spark 为载体，将算力与 Dr.Octopus 智能体平台集成，形成独立部署的一体机交付形态。用户通过浏览器进入工作台，使用项目、知识库、任务与工具能力。

用户价值：把分散采购算力、部署智能体软件和组织工作入口的需求，收拢为一个整体交付方向，减少用户分别搭建多层环境的负担。

宣传表达：**一个小盒子，集成模型、算力与智能体，部署在单位内部。**

交付边界：具体预装模型、支持任务、并发人数和性能以整机配置及实测为准，不由硬件名称推导。数据不出域方案要求所需模型与算力在盒内或客户批准的域内部署，不能以外部模型自动兜底；是否完全断网运行需另行验证。

### 1. 从一句需求延伸到实际动作

用户提出目标后，智能体可以在可用权限和工具范围内读取资料、修改文件、执行命令并返回结果。价值落在工作产物和执行过程上，例如整理后的文档、修改后的代码、生成的文件和任务记录。

宣传表达：**让 AI 接上你的文件、工具和工作环境。**

### 2. 围绕项目组织 AI 工作

工作区将项目目录、会话和相关资源组织在一起。不同项目可以分别管理，同一项目可以展开多条会话，减少材料和讨论散落各处的负担。

宣传表达：**一个项目，一个清晰的 AI 工作空间。**

### 3. 将资料积累变成可查询的知识

知识库支持文档导入、索引、检索和引用读取。资料可以持续维护，后续提问能够再次利用，无需每次重新上传同一批材料。

宣传表达：**让存下来的资料，在下一次工作中派上用场。**

### 4. 将稳定偏好与事实保留下来

长期记忆可以整理和召回用户偏好、项目决策及稳定事实，并提供查看、编辑、忘记和导出入口，减少重复说明背景。

宣传表达：**让重要约定被记住，也能被你管理。**

### 5. 将重复工作交给时间表

定时任务支持一次性、周期与 Cron 调度。经过任务级授权后，调度服务可以独立开展受支持的工作，保存执行历史，并在应用内呈现结果。

宣传表达：**把需要反复想起来的事，安排成按时执行的任务。**

### 6. 让执行过程保持可见、可干预

工具调用、权限确认、运行状态、任务历史和错误信息构成可检查的执行过程。Windows 执行器还有独立的设备授权、工具策略和本机停止入口。

宣传表达：**知道 AI 在做什么，也能决定它可以做什么。**

## 三、功能介绍与用户收益

### 1. 工作区管理

已有能力：

- 以项目目录作为工作区上下文，创建、切换与管理工作区。
- 在工作区内组织多个会话，保留各自的对话历史。
- 按当前项目发现文件与相关资源。
- 在输入中通过 `@` 引用工作区文件或目录。
- 在 Web 中浏览项目文件，并通过现有文件界面查看、编辑受支持的文本内容。

用户收益：项目材料有归属，AI 更容易获得明确上下文，用户减少反复复制路径和粘贴文件正文。

可用文案：**让需求、讨论和项目文件，在同一个工作空间里衔接。**

边界：工作区是组织与资源上下文边界，不等于操作系统级安全沙箱。长期记忆为当前实例环境的全局共享能力，也不是按工作区完全隔离。后续租户隔离放在独立运行实例与独立数据存储层落实，不能靠工作区名称代替。

### 2. 多会话与后台运行

已有能力：

- 一个工作区可以拥有多个独立会话。
- 多个会话可在资源限制内后台运行。
- 切换当前页面或会话，不会因此主动取消其他正在运行的会话。
- Web 提供流式输出、工具调用和执行状态展示。
- 断线后可以重连并重新取得状态；是否继续取决于后台服务及任务实际状态。
- 支持运行中的追加指令与后续消息控制。
- 提供结果未读提示及相关通知入口。

用户收益：可以同时推进资料分析、内容整理和开发任务，减少等待一个会话结束后才能开始下一项工作的限制。

可用文案：**把几件事分别交代清楚，让它们在各自的会话中推进。**

边界：多会话不代表无限并发，也不保证同目录并发修改没有冲突。Windows 执行器有独立的统一任务准入，不能套用 Web 多会话能力宣传为一台电脑可无限并行控制。

### 3. Web 与 TUI 双入口

已有能力：

- 使用浏览器访问 Web 工作台，管理会话、资料与设置。
- 使用 TUI 在终端开展本地智能体任务。
- 共享核心智能体能力及相应配置语义，适合不同工作习惯。

用户收益：日常资料工作可以通过浏览器访问部署在 DGX Spark 上的工作台；运维与专业用户仍可按部署需要使用终端入口。

可用文案：**在浏览器里安排工作，也能在终端里继续发挥效率。**

边界：双入口不代表全部 UI 功能完全对等，也不代表同一会话能在两个入口无缝实时接力。独立桌面版智能体客户端尚未实现；Windows Executor 是另一个职责明确的产品组件。

### 4. 文件处理、代码修改与命令执行

已有能力：

- 智能体可以通过已加载工具读取、查找、编辑与写入文件。
- 可结合项目上下文执行命令、分析输出和推进多步骤任务。
- 在开发场景中用于代码阅读、问题定位、脚本编写、文档维护与检查执行。
- 工具结果在会话中展示，便于查看实际执行情况。

用户收益：将讨论与落地动作连接起来，减少在聊天、编辑器、文件管理器和终端之间搬运内容。

可用文案：**从“帮我看看”到“帮我处理”，让工作有实际产物。**

边界：具体工具取决于运行环境、扩展与授权，代码和命令的执行质量仍需通过实际检查确认。

### 5. 附件与多格式文档处理

已有能力：

- 聊天支持附件上传与处理状态展示。
- 文档解析支持 DOCX、XLSX、PPTX、PDF、CSV、Markdown、TXT 等格式。
- 压缩导入链路可展开支持的 ZIP、TAR、GZIP、TGZ 系列容器，并处理其中受支持的文件。
- 文档提取保留部分结构定位，例如工作表与行号、幻灯片顺序、备注、文档表格与脚注等。
- 知识库链路可以结合已配置 OCR 服务处理扫描或混合 PDF。
- 能区分解析失败、跳过、截断及部分完成，便于判断材料覆盖情况。

用户收益：减少逐份打开和复制材料的工作，可围绕一批现有文档展开分析与整理。

可用文案：**把手头的文档带进来，从现有材料开始工作。**

边界：不同入口的处理策略和大小限制不同。XLSX 读取已保存的数据与公式缓存值，不等于重新计算公式；文档解析不等于完整还原版式、图片和图表，更不等于已有高保真 Office 排版编辑功能。

### 6. 知识库与资料问答

已有能力：

- 创建全局或工作区知识集合。
- 新增文本、导入文档或压缩包，并保存原文与索引。
- 管理集合和文档，包括重命名、替换原文、删除及集合重建。
- 查看导入任务状态，并对支持的任务执行取消或重试。
- 使用关键词与向量混合检索，并结合配置的重排服务改善候选排序。
- 读取命中内容与可追溯引用，在会话中查看检索依据。
- 在普通会话中切换知识问答模式，选择相关集合。

用户收益：把“文件放在哪里”逐步变成“针对资料可以问什么”，降低查找、翻阅和重复解释成本。

可用文案：**让文档成为能被反复查询、引用和维护的资料库。**

边界：需要配置相应模型服务；资料引用帮助核对依据，不保证回答始终准确，也不保证覆盖所有导入内容。扫描材料效果取决于 OCR 质量。

### 7. 知识库共享与远程挂载

已有能力：

- 将明确选择的本地全局集合通过知识库 MCP 出口发布。
- 另一个 Dr.Octopus 实例可以挂载兼容的远程知识集合。
- 远端保留数据所有权，本地以只读方式检索已挂载集合。
- 支持访问凭据与发布集合范围控制。

用户收益：在满足部署与权限条件时，复用另一个实例已经整理的资料，减少重复维护。

可用文案：**让整理好的知识，在兼容实例之间按范围复用。**

边界：当前协议限定为 Dr.Octopus `octopus-knowledge/v1`，不应宣传为兼容任意第三方知识库、企业网盘或完整团队知识协作平台。

### 8. 长期记忆

已有能力：

- 保存稳定的用户偏好、项目决策和事实约定。
- 在当前实例环境下跨会话、跨工作区召回相关记忆；后续多租户部署应将该范围限定在所属租户的独立实例中。
- 保留事实适用背景，区分某个项目的规则与用户通用偏好。
- 支持关闭、手动与自动模式。
- 提供记忆检索、创建、编辑、忘记和 Markdown 导出。
- 使用有界召回与整理策略，避免无限扩大每次调用的上下文。

用户收益：减少每次从头交代写作风格、代码约定和背景事实的负担；重要内容可以检查和纠正。

可用文案：**重要背景可以留下来，下一次工作少一些重复说明。**

边界：记忆不是完整聊天归档，不保证永不遗忘或全部自动记住；当前不提供跨设备自动同步。当前全局共享指单实例范围，不表示后续允许跨租户共享记忆，也不应把工作区宣传为记忆权限隔离区。

### 9. 自然语言定时任务

已有能力：

- 在会话中提出定时工作需求，由智能体创建和管理任务。
- 支持一次性、固定间隔与五字段 Cron 调度。
- 显式处理时区，并提供错过与重叠执行策略。
- 支持查看、更新、删除、立即运行、取消和查询历史。
- 每次运行使用独立执行会话，保存结果和相关状态。
- 创建任务后需要用户完成任务级持久授权，授权可撤销。
- 调度服务独立于 Web 会话；Web 或 Server 离线期间，可在服务和环境可用时继续执行。
- Server 恢复后可以补齐结果，并通过应用内通知、来源会话和历史入口查看。

用户收益：将周期性整理与检查转变成可管理的工作安排，减少靠记忆和重复输入维持的流程。

可用文案：**交代一次任务，安排后续执行，并留下每次工作的记录。**

边界：电脑关机、休眠、模型不可用、授权缺失或工具不可用都会影响执行。不承诺系统自动登录启动、休眠唤醒、无限补跑、邮件或即时通信推送；定时运行的工具集也不能视作普通会话工具的完整复制。

### 10. 受管后台任务

已有能力：

- 通过专门工具启动受管理的后台命令。
- 为任务保留身份、所属会话、状态、日志与退出信息。
- 支持查看、等待和停止。
- 与会话停止协调衔接，让后台执行的实际状态可见。

用户收益：适合需要一定时间的构建、脚本处理或开发服务，减少“对话停了，但后台进程还在跑”的排查成本。

可用文案：**让后台工作有状态、有日志、有停止入口。**

边界：不等于永久服务托管、自动重启或任意进程接管，也不保证恶意进程无法逃逸。

### 11. 模型服务配置

已有能力：

- 在设置中管理可用模型服务与默认模型。
- 配置自定义服务地址、模型与相应认证信息。
- 对支持的模型调整思考等级等会话选项。
- 提供 Ollama、vLLM、LM Studio 本地服务配置入口与模型发现能力。
- 将对话模型、图像服务、语音识别以及知识库模型按各自职责配置。

用户收益：在政企交付中，优先接入盒内或单位批准的域内模型服务，让模型选择与数据处理边界保持一致。通用版本的外部服务接入能力不等于域内交付时允许使用外部服务。

可用文案：**模型部署在域内，让内部工作使用域内算力。**

边界：本地服务接入不包含自动安装运行时或下载模型；发现模型列表不代表已经验证实际推理质量。模型兼容性、上下文和能力以所用服务与运行时为准。

### 12. Skills 管理

已有能力：

- 管理全局与工作区相关 Skills。
- 提供技能查看、上传、创建、编辑与删除等管理入口。
- 展示实际生效的技能目录及其来源。
- 通过技能说明沉淀任务方法、格式要求和工作步骤。

用户收益：将反复输入的工作要求整理为可复用材料，逐步建立个人或项目的方法库。

可用文案：**把做事的方法留下来，让后续任务有章可循。**

边界：Skill 是供智能体使用的说明与资源，不代表硬编码流程保证；当前不应宣传为已有完整技能商店或任意技能一键兼容。

### 13. MCP 与扩展生态

已有能力：

- 管理 MCP 服务器配置，为智能体连接外部工具提供入口。

用户收益：可以根据实际工作接入已有工具系统，而不把所有任务都限制在产品内置能力中。

可用文案：**从现有工具出发，逐步扩展 AI 能做的工作。**

边界：第三方工具需要单独安装、配置、授权与验证；扩展管理页面不是完整软件包市场。子代理依赖相应扩展与配置，不代表任意工具和权限都会自动继承。

### 14. 规划模式与交互式确认

已有能力：

- 通过已装配的 Plan 扩展进入规划模式。
- 在执行前开展问题澄清与计划整理。
- 在界面中展示规划问题、方案就绪及相关交互。
- 配合权限门禁，对工具操作进行允许、拒绝或询问。

用户收益：适合目标不够明确、步骤较多或需要先审阅方案的工作。

可用文案：**先把问题和步骤说明白，再推进执行。**

边界：计划由模型生成，仍需用户判断；规划能力是否可用取决于相应扩展。

### 15. 图像生成与参考图编辑

已有能力：

- 在普通主会话中调用图像生成工具。
- 独立配置 OpenAI GPT Image 与通义千问图像服务。
- 支持文字生成图片，以及所选协议支持的参考图编辑。
- 将产物保存为本地文件，并保留会话预览与下载入口。

用户收益：适合生成内容配图、概念草图和视觉方向参考，将文字任务与视觉素材处理放在相邻流程中。

可用文案：**讨论内容时，也能顺手生成需要的视觉素材。**

边界：当前列举的是通用版本外部服务适配，不能直接写成数据不出域交付能力；域内交付需另行验证域内图像服务，否则不启用。需要配置可用服务、模型与凭据，质量和可用性取决于服务。子代理与定时任务当前不包含该图像工具，不承诺视频生成或高精度专业设计交付。

### 16. 语音输入

已有能力：

- Web 会话提供语音输入入口。
- 服务端接收受支持音频并调用配置的语音识别服务。
- 独立管理语音服务与相应密钥。

用户收益：在长任务说明、口述想法和不便连续打字时，用语音组织需求。

可用文案：**把想法说出来，再交给 AI 继续处理。**

边界：当前核实的是语音识别输入链路，不宣传为实时双向语音通话、语音合成或完整会议录制系统。数据不出域交付需验证域内语音服务，否则不启用会向域外发送音频的功能。

### 17. Windows Executor：给你的 AI 接上一台可授权、可识别的 Windows 执行设备

已有能力：

- 独立 Windows x64 本地工具执行器，接受兼容智能体通过 MCP 接入。
- 提供文本文件读取、写入、编辑、搜索、目录查找与列举。
- 使用系统 PowerShell 执行授权命令。
- 管理客户端连接身份、能力授权、任务与历史。
- 支持默认只读、全部与逐工具自定义策略，已实现工具策略热应用。
- 提供本机 HTTP、stdio，以及显式配置的内网或 VPN HTTP 接入。
- 为设备提供持久标识与可读名称，帮助识别操作目标。
- 通过状态页、连接页和设置页管理运行环境。

用户收益：智能体可以位于本机或另一台受支持的机器，通过明确授权触达 Windows 环境中的工作材料和工具。

可用文案：**给你的 AI 接上一台可授权、可识别的 Windows 执行设备。**

边界：执行器自己不运行第二套模型规划循环。Linux/macOS 执行器未实现；远程接入限定受支持的私有网络方式，不等于任意公网远程控制。

### 18. 浏览器操作

已有能力：

- 配合 Chrome 或 Edge 扩展，通过 Native Messaging 连接本地执行器。
- 列出浏览器连接实例与标签页。
- 打开网页、导航，并在限制内关闭任务创建的标签页。
- 获取页面 DOM 快照和可选视口截图。
- 基于当前快照的元素引用点击、填写、选择与滚动。
- 在扩展弹窗中查看连接、暂停与故障信息。
- 使用页面遮罩、高亮等反馈，帮助用户识别正在执行的页面。

用户收益：适合网页资料收集、重复信息填写，以及需要借助现有浏览器登录态完成的受支持操作。

可用文案：**让 AI 看见网页结构，围绕真实页面开展操作。**

边界：是有限页面工具，不提供任意网页脚本执行；复杂站点、跨域或嵌套 frame、验证码和反自动化可能需要人工介入。当前浏览器录制与本地智能重放尚未实施，不能写成已支持。

### 19. Windows 桌面操作

已有能力：

- 已接入并启用受管 Windows-MCP 后端。
- 支持桌面、显示器或指定区域截图，以及 Windows UIA 控件树观察。
- 提供点击、输入、滚动、快捷键与已有窗口切换。
- 提供显示器信息与控制状态查询。
- 结合设备授权、任务状态、本机 Esc 与托盘停止入口管理执行。

用户收益：为缺少 API 的 Windows 应用提供通过界面交互完成部分任务的路径。

可用文案：**让智能体在授权下，通过 Windows 界面完成受支持的操作。**

边界：所有 Computer 工具均需桌面控制授权，包括截图；不应称为无需接管的只读观察。独立电脑、多显示器、不同 DPI 及正式发行验收仍有待办，不宣传为任意软件都能稳定自动操作。

### 20. 跨机文件传输

已有能力：

- 智能体通过 MCP 准备上传或下载，再由其本地 HTTP 工具传输文件流。
- 将智能体所在环境的文件发送到 Windows 执行器，或取回执行器上的文件。
- 使用临时、绑定任务与方向的传输凭据。
- 提供传输状态、取消与结果查询。
- 默认单文件上限为 2 GiB，可受设置与运行条件约束。

用户收益：为远端智能体与 Windows 本地处理衔接文件，减少将大文件内容塞进模型上下文或人工中转。

可用文案：**让文件在智能体环境与 Windows 执行设备之间有序流转。**

边界：智能体自身需具备二进制上传下载和本地保存工具；当前不是网盘同步、断点续传或任意 URL 拉取服务。大小上限不是速度保证。

### 21. 权限与执行管理

已有能力：

- 智能体侧提供询问、自动和全量等权限模式及工具策略。
- 支持全局与受信项目配置，并在工具调用边界执行检查。
- 可批准单次操作，或在满足范围条件时给予会话授权。
- 保存受限、脱敏的权限审查记录，并提供查询工具。
- 定时任务使用独立的持久授权与撤销机制。
- Executor 另有设备能力授权与工具级策略。

用户收益：将不同信任程度的任务放在对应的权限配置下，减少“要么每步确认，要么全部放开”的使用负担。

可用文案：**让每一类工具的使用，都有明确的授权边界。**

边界：权限门禁不等于安全沙箱或零风险保证，也不能保证识别所有危险命令。不同层的权限各自生效，不能混为一套通用授权。

### 22. DGX Spark 一体机交付、独立部署与开源

已有能力：

- 支持 npm 安装，通过 CLI 管理 Gateway、运行依赖和诊断。
- 提供 Linux AMD64 Docker 成品镜像及对应安装方式。
- 数据与配置保存在部署环境的数据目录或持久卷中。
- 原创项目代码使用 MIT 许可证，第三方组件保留各自许可。

产品交付方向：将模型、算力与智能体平台集成到 DGX Spark 小盒子中，在单位内部独立部署，用户通过域内浏览器进入工作台。后续按多租户方向组织独立实例与存储，以数据不出域为启用功能与服务配置的约束。

用户收益：以一体化交付减少分别搭建硬件算力、智能体服务和使用入口的负担，让团队围绕一台设备建立 AI 工作环境。

可用文案：**数据不出域，模型与算力在内部；一个小盒子，连接资料、知识与任务。**

后续部署方向：采用多租户管理，每个租户使用独立镜像部署独立运行实例，分别管理数据与持久化存储。镜像是部署产物，数据隔离需要由实例、存储挂载和访问控制共同落实；独立镜像本身不等于完成隔离。

边界：上述 npm 与 Docker 能力是当前软件发行依据，其中 Linux AMD64 成品镜像不能直接作为 DGX Spark 整机兼容性证明；目标设备的镜像、依赖与模型适配需单独验证。当前多租户管理、租户隔离与全链路不出域尚未完成验收。正式交付需配套鉴权与访问控制；当前应用没有内置完整公网登录边界。域外模型、OCR、图像等服务会改变数据流向，不纳入未经批准的数据不出域方案。开源不等于整机硬件、计算资源和交付服务免费。

## 五、适用人群

**核心目标客户按以下顺序展开，后文通用岗位人群用于补充具体使用角色。**

### 核心客户 A：政府部门

需求：在指定数据域内使用内部政策资料、工作制度和项目文档开展辅助工作，减少向公共云 AI 上传材料的需要。

适用场景：政策资料查询、公文与汇报草稿、内部制度问答、项目材料汇总和工作简报。重点表达模型与算力域内部署、原文引用和人工复核，不宣传为自动行政决策或替代审批。

### 核心客户 B：国有企业

需求：围绕经营管理、项目建设、采购与内部制度使用 AI，同时保持业务资料的数据边界。

适用场景：项目资料整理、采购文件要点提取、经营分析草稿、制度问答和周期报告。重点表达内部知识利用与流程辅助，输出由负责人员审阅，不承诺自动作出法律、采购或经营决策。

### 核心客户 C：公共事业单位

需求：在受控网络与业务环境内，利用运行规程、设备手册、服务流程和内部记录辅助工作。

适用场景：规程检索、设备资料查询、工单摘要和事件材料整理。重点表达域内资料复用与来源核对，不宣传为直接控制关键基础设施或替代专业人员的安全判断。

### 核心客户 D：有数据保密要求的企业

需求：内部研发、客户、项目和经营资料不宜传递到外部 AI 平台，但业务人员需要文档分析、内容整理和知识问答。

适用场景：研发知识库、项目资料分析、技术方案草稿、内部培训与管理报告。重点表达模型、算力与数据处理链路位于客户指定域内。

共同口径：**面向数据保密需求提供独立部署方案。** 不由客户类型直接推导产品已经具备涉密系统适用资格、安全认证或行业合规结论。

### 1. 个人开发者与独立开发者

需要在代码、文档、脚本、测试与资料之间不断切换。适合重点介绍项目工作区、文件引用、命令执行、多会话、受管后台任务和终端入口。

沟通角度：**让 AI 接入已有项目，协助把需求落实到文件和检查结果。**

### 2. 产品经理与运营人员

经常整理需求、对照资料、撰写说明并维护周期性内容。适合重点介绍文档分析、知识库、写作偏好记忆和定时整理。

沟通角度：**把零散材料组织起来，让整理、写作和周期复盘更连贯。**

### 3. 内容创作者与研究型写作者

需要反复利用资料、保持表达风格、生成不同版本内容。适合重点介绍资料库、引用、Skills、长期记忆和图像生成。

沟通角度：**让资料积累和创作方法，在每次内容工作中继续发挥作用。**

### 4. 咨询、研究与方案人员

面对多份报告、方案和项目背景，需要追溯依据。适合重点介绍多格式文档、工作区知识集合、问答和引用查看。

沟通角度：**围绕一批资料开展分析，并把结论与来源放在一起检查。**

### 5. 团队与组织

需要统一提供 AI 工作入口，积累资料和工作规范，同时与其他租户保持数据边界。适合重点介绍 DGX Spark 一体机独立部署、Web 工作台、Skills、MCP，以及后续多租户管理和租户独立实例方向。

沟通角度：**先把工具与工作方法沉淀下来，再逐步扩展适用范围。**

边界：已确认的后续方向是多租户管理与每租户独立镜像实例、独立数据存储。组织账号、RBAC、审批流和多人实时协作需分别定义与实施，不能由租户实例隔离推导为全部已有。

### 6. Windows 重度工作用户

日常依赖本机文件、PowerShell、浏览器业务系统和桌面软件。适合重点介绍本地执行器、设备授权、浏览器与桌面操作。

沟通角度：**把 AI 接到每天使用的 Windows 工作环境。**

## 六、应用场景与示例需求

以下是能力组合示例，不是已完成交付的行业解决方案。示例中的文件应使用测试或已获授权的材料；涉及写入、提交或外部发送的步骤需要相应授权与结果核验。

### 场景 1：已有代码项目的功能梳理

痛点：接手一个项目，文档与代码分散，难以快速掌握功能。

使用方式：选择项目工作区，让智能体阅读 README、模块和已有设计，整理功能清单、入口与待办。

示例需求：“帮我梳理这个项目已经实现的功能、使用入口和限制，生成一份面向新同事的说明。”

传播角度：**先把项目读明白，再开始下一步工作。**

### 场景 2：开发问题定位与修复

痛点：错误信息、代码位置和验证命令之间需要人工反复切换。

使用方式：提供错误与复现条件，结合文件搜索、编辑和命令执行定位并验证修改。

示例需求：“根据这段错误日志定位问题，修改后运行相关检查，并说明还有哪些没有验证。”

传播角度：**把定位、修改和验证放进一次连续工作中。**

### 场景 3：项目文档维护

痛点：代码已变化，使用说明还停在旧版本。

使用方式：对照实际实现与文档，整理差异，再生成待审阅的更新。

示例需求：“检查安装说明与当前配置是否一致，修正文档，并保留仍未实现功能的明确标记。”

传播角度：**让文档跟上项目实际状态。**

### 场景 4：产品宣传素材整理

痛点：功能清楚，但无法直接转化成面向用户的表达。

使用方式：读取产品资料，整理定位、用户收益、痛点、场景与文案，并区分现有功能和规划。

示例需求：“根据当前项目整理功能卖点、适用人群、使用场景和官网文案，不编造尚未实现的能力。”

传播角度：**从产品事实出发，把技术能力讲成用户价值。**

### 场景 5：多份报告的主题分析

痛点：资料量大，查找同一问题的不同论据很耗时。

使用方式：将报告导入知识库，指定集合提问，要求列出支持与冲突依据。

示例需求：“根据这批报告整理对市场需求的主要判断，列出一致观点、分歧和对应引用。”

传播角度：**带着问题读资料，让结论有处可查。**

### 场景 6：产品手册与 FAQ 草稿

痛点：同类产品问题需要反复翻手册回答。

使用方式：导入产品说明、常见问题和流程文档，生成带引用的回答草稿。

示例需求：“根据当前产品手册回答这组问题；资料没有说明的部分请明确列出。”

传播角度：**让现有手册成为日常答疑的资料基础。**

前提：这是答复辅助，不是已经接入客服渠道并自动发送消息的客服系统。

### 场景 7：扫描资料整理

痛点：扫描 PDF 查找困难，人工录入费时。

使用方式：配置 OCR 服务后，将受支持资料导入知识库，核对识别结果并按主题检索。

示例需求：“从这批扫描资料中找出与项目交付条件相关的内容，列出原文位置和待人工核对项。”

传播角度：**让扫描材料也有机会进入可检索的工作资料库。**

### 场景 8：运营数据初步整理

痛点：表格字段杂乱，需要先理解口径再总结。

使用方式：读取 CSV 或 XLSX 已保存数据，梳理字段、缺失和异常，形成分析草稿；必要时运行脚本。

示例需求：“分析这份运营数据，说明字段含义、明显异常及统计口径；需要计算的部分用脚本核对。”

传播角度：**先整理数据和口径，再开展分析。**

前提：数据正确性与业务口径需人工确认，不默认具备完整 BI 平台功能。

### 场景 9：内容创作与风格复用

痛点：同一品牌每次都要重新说明风格和禁用表述。

使用方式：将品牌资料放入知识库，将稳定写作要求整理进 Skill 或记忆，生成多版内容。

示例需求：“参考品牌资料，按之前确认的语气生成一篇产品介绍，并标明资料里无法支持的描述。”

传播角度：**让品牌资料和表达习惯一起参与创作。**

### 场景 10：文字与配图的连续准备

痛点：文案完成后，还要另外切换工具生成视觉素材。

使用方式：先明确内容与画面目标，再通过已配置图像服务生成或编辑图片，保存产物。

示例需求：“根据这段活动文案生成三种配图方向，选定方向后生成一张用于内部评审的图片。”

传播角度：**从内容构想到视觉草稿，减少工具之间的搬运。**

### 场景 11：周期性工作简报

痛点：每周总要重复汇总同一目录的记录。

使用方式：为明确目录与输出位置创建定时任务，授予必要权限，保存每次结果。

示例需求：“每周五下午读取本周工作记录，生成周报草稿，保留未完成事项并保存到指定目录。”

传播角度：**把重复整理安排进日程，让每次结果可回看。**

### 场景 12：日志或文件周期检查

痛点：简单检查容易忘记执行，事后难回溯。

使用方式：定时运行受支持检查，保存发现与错误，并在应用内查看结果。

示例需求：“每天检查指定日志中新增的错误记录，按类型整理摘要；读取失败要单独报告。”

传播角度：**把检查变成有记录的习惯。**

前提：环境与服务需保持运行；不替代专业监控告警系统。

### 场景 13：公开网页资料收集

痛点：多个网页需要反复打开、阅读并摘录。

使用方式：通过浏览器工具或另配的联网工具打开指定来源，整理可访问内容和来源链接。

示例需求：“阅读这几个公开页面，整理它们的功能差异，并保留来源与采集时间。”

传播角度：**围绕明确来源开展网页整理。**

前提：目标页面可访问且允许相应使用；不承诺绕过登录、付费墙、验证码或反自动化机制。

### 场景 14：网页表单填写辅助

痛点：在浏览器里重复填写相似字段。

使用方式：观察页面，按明确数据填写受支持字段，并在关键提交前核对。

示例需求：“按这份测试资料填写网页表单，填写完成后停在提交前，列出已填字段让我确认。”

传播角度：**让重复填写有明确数据来源和检查步骤。**

前提：真实支付、发布、外部通知等后果需另行明确授权。

### 场景 15：Windows 本地文件处理

痛点：远端智能体难以直接使用本机文件环境。

使用方式：通过 Executor 授权文件与 PowerShell 能力，对指定目录进行查询和受控处理。

示例需求：“列出这个测试目录的文件类型与重复命名情况，先生成整理方案，确认后再执行修改。”

传播角度：**让 AI 围绕本机材料开展具体工作。**

### 场景 16：缺少 API 的桌面软件操作探索

痛点：已有 Windows 软件无法通过接口自动化。

使用方式：通过截图与 UIA 观察当前界面，使用受支持点击、输入和快捷键推进有限步骤。

示例需求：“观察当前测试应用，定位导出入口，生成操作计划，必要时在授权后执行。”

传播角度：**为已有桌面流程增加一条智能体交互路径。**

前提：需实际验证目标软件、显示环境与步骤，不将该场景宣传为所有业务软件的现成方案。

### 场景 17：远端分析与 Windows 处理衔接

痛点：文件在远端环境生成，本机仍有后续处理需求。

使用方式：通过 Executor 文件传输将文件送到 Windows，完成授权处理后按需要取回结果。

示例需求：“把这个生成文件发送到指定 Windows 测试目录，确认上传成功后再继续下一步。”

传播角度：**把远端生成与本机处理连接起来。**

### 场景 18：个人工作规范沉淀

痛点：提示词越积越多，很难知道哪份仍有效。

使用方式：将方法整理成 Skills，将稳定偏好与事实纳入记忆，定期检查和清理。

示例需求：“把我确认过的文档风格整理成一份 Skill，将通用偏好与仅本项目适用的规则分别写清楚。”

传播角度：**把反复交代的要求，整理成可维护的工作资产。**

### 场景 19：新人理解内部资料

痛点：新成员需要从大量资料中理解术语和流程。

使用方式：在受控部署中整理相关文档，通过知识问答帮助生成学习提纲和解释草稿。

示例需求：“根据这组项目文档，整理入门顺序、核心术语和十个常见问题，每条附对应资料。”

传播角度：**让已有文档更容易被新使用者理解。**

前提：访问控制由部署与外部系统共同保证，不假定产品已有完整企业账号权限。

### 场景 20：长任务与并行事项管理

痛点：等构建、分析或脚本完成时，其他工作无法衔接。

使用方式：将不同事项分到独立会话，使用受管后台任务查看长任务日志与状态。

示例需求：“运行这项检查并保留日志，我先切换到另一个会话处理说明文档，结束后再查看结果。”

传播角度：**长任务继续运行，其他事项也有自己的推进空间。**

## 八、可直接改写使用的介绍文案

### 1. 极简版

Dr.Octopus：数据不出域，模型与算力就在单位内部。

### 2. 简介版

Dr.Octopus 是一款面向政府、国企、公共事业单位及有数据保密要求企业的 AI 智能体一体机。基于 DGX Spark，将模型、算力与智能体平台部署在单位内部，让内部资料的分析、检索与任务处理在指定数据域内完成，通过域内浏览器工作台使用 AI。

### 3. 官网介绍版

数据不出域，让 AI 在单位内部开展工作。

Dr.Octopus 基于 DGX Spark，将模型推理、算力与智能体平台集成在一个小盒子中，独立部署于单位内部。面向政府、国企、公共事业单位和企业的数据保密需求，围绕指定数据域构建资料处理与 AI 工作环境。

通过域内工作台，工作人员可以查询内部制度、分析项目文档、整理汇报材料、建设业务知识库，并安排周期任务。在域内处理链路配置完成的方案中，内部材料无需上传公共云 AI，即可参与知识问答与任务处理。

知识库、长期记忆、文件工具和任务管理共同服务实际工作；配合授权的 Windows 执行器，还可连接单位内部终端上的文件、浏览器与桌面操作。

模型在内部，算力在内部，资料在指定数据域内处理，让 AI 服务于已有的数据管理边界。

后续平台方向：在一体机内采用多租户管理，为每个租户通过独立镜像部署独立实例，隔离工作数据与存储。该段用于后续版本介绍，正式发布时应以实际实现和隔离验收结果为准。

### 4. 开发者版

Dr.Octopus 基于 Pi，提供 Web 与 TUI 入口，以工作区和独立会话组织智能体任务。结合文件工具、命令执行、受管后台任务、知识检索、长期记忆及 MCP 扩展，可以围绕已有项目开展阅读、修改、检查和文档维护。模型与工具由你配置，执行结果通过日志、状态和产物核验。

### 5. 知识工作者版

资料越来越多，重复说明也越来越多。

Dr.Octopus 帮助你将文档整理成可检索的知识集合，在问答时查看引用，将稳定偏好与项目约定保存为可管理的长期记忆。围绕已有材料继续分析、写作和整理，让每次积累都有机会服务下一次工作。

### 6. 自动化版

把反复需要处理的事项，安排成有记录的任务。

Dr.Octopus 支持通过自然语言管理一次性与周期任务。完成必要授权后，在服务和环境可用时按计划执行，保存运行状态、历史和结果，并通过应用内入口查看。适合逐步沉淀周期简报、项目资料整理和日志检查等工作。

### 7. Windows 执行器版

Dr.Octopus Executor 为兼容智能体提供 Windows 本地执行能力。

通过明确的设备身份、能力授权和工具策略，将文件、PowerShell、浏览器与桌面操作开放给可信客户端。本机和受支持内网接入共享任务与结果管理，让智能体可以围绕指定 Windows 环境开展受控工作。

桌面与浏览器能力需结合实际应用验证，当前发行验收范围以对应版本记录为准。

### 8. 社群发布版

做项目时，AI 对话、资料、文件和重复任务常常散在不同地方。

Dr.Octopus 想把这些环节组织起来：用工作区管理项目，用知识库复用材料，用长期记忆保留约定，用定时任务安排重复工作，再通过工具和 MCP 接到实际执行环境。

我们将模型、算力与智能体平台集成在 DGX Spark 小盒子中，部署在单位内部，围绕数据不出域要求组织资料分析、知识问答和任务执行。用户通过域内 Web 工作台使用，后续采用每租户独立镜像实例与独立存储，面向政府、国企、公共事业单位和企业建立清晰的数据使用边界。

### 9. 政企客户沟通版

内部资料不能随意上传外部平台，AI 的应用就需要从部署方式开始考虑。

Dr.Octopus 将模型、算力与智能体平台集成到 DGX Spark 一体机，在单位内部独立部署，围绕数据不出域要求处理内部知识、项目文档与日常任务。工作人员通过域内浏览器访问，无需逐台搭建模型环境，即可开展资料检索、文档分析、内容起草和周期性工作整理。

面向政府、国企、公共事业单位及有数据保密要求的企业，以域内部署承载 AI 应用，以实际配置和验收落实数据边界。

## 十一、常见问题的宣传口径

### 1. 适合完全没有技术背景的人吗？

Web 提供直观的会话和设置入口。产品以 DGX Spark 一体机独立部署，用户通过浏览器使用，减少逐台电脑安装运行环境的负担。整机初始化、模型服务和工具接入仍需完成相应配置，不能仅凭一体机形态承诺所有功能开箱即用。

### 2. 是否必须使用云端模型？

不需要。面向数据不出域的交付方案，模型与算力部署在盒内或客户批准的域内环境，不依赖外部云端模型处理内部资料。具体模型及功能组合需在目标设备上验证。

### 数据不出域是否只要求对话模型部署在内部？

不只如此。凡是处理业务数据的已启用环节，包括向量化、重排、OCR、图像或语音、MCP 工具、日志、备份和运维通道，都需要遵守客户确定的数据域边界。缺少合适域内服务的能力不应自动改用外部服务。

### 是否意味着已经通过保密或合规认证？

不是。产品面向政府、国企、公共事业单位和企业的数据保密需求，提供域内部署方向。数据不出域是部署与运行约束，不等同于涉密资质、安全认证或合规结论，相关表述必须有对应的有效证据。

### 3. 同一个盒子如何隔离不同租户的数据？

后续采用多租户管理，每个租户使用独立镜像部署独立运行实例，并隔离各自的数据与持久化存储。需要配套租户身份、请求路由、访问控制和存储配置完成隔离，当前不能宣称已通过相关验收。租户隔离与数据不出域是两个需要分别落实的边界，域内推理共享算力也不代表允许租户间共享业务数据。

### 4. 开源是否意味着没有费用？

原创代码采用 MIT 许可。模型 API、硬件、部署和第三方工具可能产生费用，应按自己的配置核算。

### 5. 能否完全自动完成所有任务？

任务能否完成取决于模型、资料、工具、权限和环境。适合先从边界清楚、结果容易验证的任务开始，逐步扩大范围。

### 6. 定时任务需要一直开着网页吗？

不需要一直开着网页。调度服务独立运行，但所在设备、服务、模型和所需工具必须可用；电脑关机或休眠期间不承诺执行。

### 7. 可以自动使用任何 Windows 软件吗？

当前提供桌面观察与有限输入工具，具体软件需要单独验证。Computer 已启用，但独立硬件及正式发行验收仍有未完成项。

### 8. 是否已经可以录制一遍浏览器操作再自动重放？

尚未实现。当前浏览器扩展提供连接与有限页面操作；录制、工作流编译和本地智能重放已接受设计方向，仍待实施与验证。

### 9. 能给整个公司直接使用吗？

产品以 DGX Spark 独立部署的一体机为交付方向，后续支持多租户使用，每租户通过独立镜像部署独立实例并隔离数据。当前不能将该方向描述为已完成交付验证，也不能推导为已具备完整组织权限、多人协作或合规认证。实际上线需完成整机适配、租户管理、访问控制、隔离验证及 HTTPS 等配套能力。
