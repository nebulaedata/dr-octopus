# 智能体首页与 Session 预热

作者：Codex · 2026-09-03

## 已实现的行为

- 未选中 Session 时，根首页使用 General workspace；Workspace 首页使用当前工作空间。
- 浏览器为每个工作空间保留一个草稿 UUID。TanStack Router 在空白首页路由匹配后立即启动非阻塞预热，页面通过同一个 TanStack Query 缓存订阅准备状态，准备期间可以输入文字。响应式布局切换和页面重新挂载复用草稿 UUID。
- 路由链接预加载不会创建 RPC 进程；已有 Session、设置和技能路由也不会触发空白会话预热。
- 草稿元数据仅保存在 Server 内存中，不写入 SQLite `sessions` 表，不进入侧栏目录。Pi 启动仍需要一个仅含 header 的 JSONL 文件，使用现有公开 bootstrap API 创建。
- 首次发送先登记相同 UUID、Pi Session 路径、模型和偏好，再通过原有 WebSocket 发送消息，并跳转到聊天页。登记操作幂等，列表创建时间采用首次登记时间。
- 模型、权限、附件、文件引用、命令与扩展 UI 继续使用原 Composer；草稿阶段不展示需要已登记会话的派生、命名、导出等命令。
- 侧栏 New session 和 `/new` 打开新草稿首页；显式 HTTP 创建会话接口保留原契约。

## 生命周期与资源边界

草稿会使用一个真实 Agent 子进程，占用现有运行时容量。运行中的页面订阅保护该进程；离开页面后，现有运行时淘汰策略仍生效。每分钟检查一次草稿，回收至少十五分钟未活动且没有订阅或运行操作的未登记草稿，删除其 JSONL 及附属文件。Server 正常关闭时清理剩余草稿；异常强制终止可能留下 header 文件，但不会留下 SQLite 会话条目。

最多保留 64 个准备中或未登记的草稿元数据，实际活跃进程仍受现有 global/workspace 容量限制。重复准备请求共享同一个启动 Promise；跨工作空间使用同一 UUID 被拒绝。启动失败可以重试。Server 重启或草稿过期后，首页的重试会重新准备进程。

未修改任何内置或已安装扩展，未改动串行 admission 队列，也未调整 Node old-space 上限。

## CLI 导入与缓存撤回

Logo、交互安装提示按需导入；Agent 公共导出使用惰性终端入口，因此 Server 导入 Agent 包也不会带入 `oh-my-logo` 或项目的 `terminal-ui`。Pi 及外部扩展自身的终端依赖不在本次改动范围内。

按用户后续要求，已移除新增的 Node 编译缓存配置、启动前主动写出缓存及缓存专用测试。应用不再主动设置 `NODE_COMPILE_CACHE`。首页预热、草稿生命周期和 CLI 按需导入继续保留。

移动端（小于 768 px）Composer 工具栏仅显示智能体模式、模型选择、权限、提交四项，保持单行，按钮仅显示图标，隐藏选中文字和下拉箭头；菜单内保留完整选项。运行中模式和模型禁用，提交仍通过原有消息流程发送。其他工具栏功能仅在桌面显示。首页四个任务建议胶囊已删除。小章鱼放大到移动端 96 px、桌面端 104 px，使用 8 秒 CSS transform 循环模拟海浪漂浮，并在系统设置减少动态效果时停用。
