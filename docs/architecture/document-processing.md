# 统一文档解析与 ZIP 附件

设计决策见 [ADR-0048](../adr/0048-shared-streaming-document-processing.md)。

## 生产调用链

- 附件：格式证据识别 ZIP → `archive-text-extract` 准入 → 现有隔离处理子进程 → `extractDocument()` → 公共文件解析器 → 有界 `document.json` / `chunks.jsonl`。
- 知识库：流式校验原文 SHA-256 → 公共文件解析器 → 每段 IPC 等待消费确认 → 最多 64 个分块组成一批 → 嵌入并写入未发布修订 → 文档完整成功后发布。
- 压缩导入：`expandArchiveFile()` 按顺序提供当前成员的私有临时文件；知识库流式转存内容寻址 Blob，附件直接解析。推进迭代器或提前返回后，当前成员文件被释放。

入口不反向引用自己的 barrel，字节兼容入口与文件入口最终调用同一 Office 解析器。`parseDocument()` 保留小文件调用方式；同步 `expandArchive()` 标记为弃用，生产入口已全部改用文件迭代器。

## 格式行为

| 格式     | 解析策略                                         | 定位与语义                                                                               |
| -------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| DOCX     | 增量 WordprocessingML；不构建 DOM                | 正文、表格行、脚注、尾注、页眉页脚；排除删除修订与域指令                                 |
| PPTX     | 按 presentation 关系顺序读取 DrawingML 段落      | 实际幻灯片序号及对应演讲者备注；不索引孤立幻灯片                                         |
| XLSX     | 增量工作表 XML；共享字符串与定长偏移索引置于磁盘 | 工作表和行号、稀疏列、富文本、布尔值、缓存公式值；日期按 1900/1904 日期系统输出 ISO 文本 |
| ZIP 附件 | 顺序展开，支持嵌套 ZIP/TAR/GZIP                  | 成员 DOCX/PPTX/XLSX/PDF/TXT/MD/CSV 进入公共解析器；其他成员记录跳过                      |

XLSX 不计算公式，不还原 Excel 的全部显示格式、图表和图片；读取已保存的单元格值。PDF 和普通文本继续使用现有有界解析器，本次只保证 Office 与压缩包路径不再整体缓存解压内容。

ZIP 的 `units[].locator.archivePath` 和检索分块中的同名字段保留来源。根标识 `archive.zip` 表示当前附件，原始附件名仍在附件元数据中。`ARCHIVE_SKIPPED`、`ARCHIVE_FAILED`、`ARCHIVE_EMPTY`、`ARCHIVE_TRUNCATED` 区分各成员结果；损坏成员已经产生的文本会回滚。外层压缩包校验失败时，整个附件处理失败。

附件可在总字符预算处截断，根 `truncated` 为权威完整性标记。知识库不接受截断：任一解析、嵌入或写入失败都不会发布本轮修订；已经写入的不可见修订沿用既有索引清理机制。

## 资源与生命周期

| 边界         | 默认限制                                                                |
| ------------ | ----------------------------------------------------------------------- |
| 输入文件     | 100 MiB，附件另受其上传策略约束                                         |
| 普通压缩包   | 2,000 个条目、累计 256 MiB 实际解压数据、单条目 100 MiB、嵌套深度 4     |
| Office 容器  | 10,000 条目、累计 512 MiB 实际解压数据、单条目 100 MiB                  |
| ZIP 中央目录 | 8 MiB 元数据，拒绝加密、链接、ZIP64、分卷及重复/非法路径                |
| 压缩比       | ZIP 单条目及 GZIP 实际输出最多 100 倍                                   |
| XML          | 256 层；未完成标记/文本约 1 MiB 加一个输入块；单段/行 1 MiB             |
| Office 输出  | 一千万字符、十万段；500 张幻灯片、100 张工作表、两百万单元格/共享字符串 |
| 知识库索引   | 两万个分块；每批至多 64 个分块及其向量                                  |

Office 在产出正文前逐条校验 CRC、实际大小和关系安全；验证输出立即丢弃，再按需打开相关 XML。这样即使附件提前停止取正文，也不会漏过包尾的活动内容或外部关系。代价是额外解压读取，换取有界内存与完整安全校验。

临时文件由 `mkdtemp` 创建，不以包内路径落盘。附件临时文件位于任务输出目录的 `scratch`；知识库位于父进程创建的 `parser-*`。父进程等待子进程退出后清理，因此解析子进程超时、取消和被终止时同样可回收。知识库解析超时只计算解析工作时间，等待分块嵌入与写入的消费时间不计入解析预算。
