# 定时任务目录与执行历史

## 用户入口

`/schedules` 提供「任务管理」「执行历史」两个入口。任务卡片平铺并标注工作区，整个列表统一分页，工作区默认全部，可结合名称与状态筛选。状态包括全部未归档、待执行、已完成、已暂停、需处理、已归档。执行历史也默认全部工作区，统一排序分页；每条运行标注工作区，详情使用该运行真实所属工作区打开。

新任务仅通过会话中的 `scheduler_create` 创建。页面不提供新建按钮或创建表单，原 HTTP 会话创建接口已移除；页面保留已有任务的编辑、授权、运行和归档。

历史按任务名称、执行结果、计划执行日期范围筛选。日期范围使用官方 shadcn Calendar + Popover（range 模式），将本地开始日 00:00 和结束日 23:59:59.999 转成 UTC。未选范围表示不限；未完成选择时不能提交。每页 20 条，查询额外一条决定是否还有下一页，不伪造总数。每条历史标注手动运行或定时触发，通过 Dialog + Collapsible 查看只读执行内容。

## 归档与保留

既有 DELETE 行为是软删除，本次 UI 明确命名为「归档」。新增 POST `/:taskId/archive` 路由复用同一事务语义，保留旧 DELETE 接口兼容性。归档继续使用现有 `deletedAt` 字段，无数据库迁移；历史软删除数据也进入已归档列表。

归档将禁用计划、清空下一次执行时间、标记授权失效、跳过排队任务并请求取消活动运行。任务、Run、transcript、授权审计均保留。归档后的任务不能编辑、授权或再次运行，支持查看历史、恢复任务和彻底删除。

恢复和彻底删除需要用户控制凭据，不注册模型工具。两者校验工作区/来源会话范围、当前归档状态、预期 revision，并拒绝存在 queued/claimed/dispatching/running 的任务。旧授权撤销成功后才能继续，授权审计保留，普通会话授权逻辑不变。

- 恢复：清除 deletedAt 和授权引用，保持暂停、disabled、无下次执行时间，标记待授权。保留任务 ID 与历史；重新授权后由用户显式恢复执行。已过期的一次性计划需要先编辑执行时间。
- 彻底删除：删除独立运行目录、Run、结果投递记录及任务行。已有幂等回执替换为去除名称/提示词等内容的删除回执，保留请求指纹防止旧创建请求重放后重建任务。必要授权审计、来源会话中已回显的消息以及任务在工作区创建的产物不删除。
- 文件删除先于数据库事务提交，仅处理数据库记录对应的 scheduler/runs/<runId>，验证真实路径且拒绝重定向目录。文件或存储失败会保留归档记录供重试；文件删除不可回滚，因此失败后部分 transcript 可能已清理。确认弹窗说明不可恢复性，未收到成功响应时保留弹窗与同一请求 key。

一次性计划到期后不再安排下次触发；存在排队或活动 Run 时显示执行中，结算后显示已完成。需处理状态优先展示授权拦截，最终执行结果以 Run 为准。手动运行不消费未来的定时触发。

## 边界与接口

- Agent Repository 在 SQL 中完成筛选后分页，使用工作区和可选来源会话双重范围约束。
- `list` 接受 status、q、limit、offset；默认排除归档。
- GET `/api/scheduled-tasks` 接受 workspaceId（可选）、status、q、limit、offset。Server 从可信工作区目录取得范围，以 updatedAt DESC、id DESC 合并各工作区有序结果，每个来源仅保留 100 条缓冲，累计消费至 offset + limit；任一工作区失败则整页失败。指定工作区时直接使用该工作区分页。
- GET `/api/scheduled-tasks/history` 以同样的有界合并方式按计划时间的实际时刻 DESC、id DESC 合并历史，支持可选 workspaceId 与日期/结果/名称条件。
- POST `/:taskId/restore` 与 `/:taskId/purge` 转发 Agent 对应 mutation，均要求 If-Match 和 Idempotency-Key；返回 restored 或 purged。
- `history` 有 taskId 时查询单任务，未指定时查询调用范围的全部任务。归档任务的 transcript 沿用原有只读权限检查。
- GET `/api/workspaces/:workspaceId/scheduled-tasks/history` 暴露工作区历史；原单任务 runs 接口也支持分页和时间/结果过滤。
- 历史排序为 scheduledFor DESC、id DESC；名称使用参数化的 literal substring 查询，百分号不作为通配符。
- 查询结果中的 taskName 是当前任务名称，不声称是运行时名称快照。Run 的实际提示词与执行内容仍来自不可变执行记录。
- 协议版本保持 3，扩展查询需要更新并重启 scheduler；旧 daemon 对未知查询字段明确报错，不会静默忽略筛选。
- 分页采用 offset：后台新增记录可能使翻页边界移动，刷新后以最新记录为准。

## 验证

隔离数据库测试覆盖归档可见性、历史保留、分页、字面量搜索、时间范围、结果过滤、范围隔离、恢复后的授权门禁、活动运行删除拦截、文件清理与路径逃逸防护、删除后幂等重放。浏览器验证不彻底删除用户已有任务。
