# 通用定时任务结果与通知闭环

## 目标与职责

所有定时任务共享同一交付流程，新闻、文件分析、巡检等只影响内容，不影响投递机制。Scheduler 保存执行事实、真实 Pi 会话及运行历史；Server 保存用户可见的会话登记、通知与已读状态；Web 展示结果和后续操作。查看结果不启动模型或占用执行 Runtime。

## 执行与交付

1. 每次运行使用独立执行会话，关联 taskId、runId、workspaceId 和来源会话。任务授权只在这次受控运行中应用。
2. 运行进入成功、失败、待人工处理、超时、取消、中断等终态后，Server 通过受控 SDK 查询已结算结果并登记会话。尚未创建执行会话的失败应由报告会话承载原因，明确没有执行模型。
3. 执行会话与执行记录保持一对一；来源会话展示简短状态与结果链接。完整结果保留在执行会话中，不重复复制整份输出到来源会话。
4. 创建持久化通知，并在同一数据库事务中更新结果会话和来源会话的通知版本。重复扫描、重启和通知重试必须命中相同 eventKey，不能产生重复会话或再次点亮已读结果。
5. 用户从会话列表、全局通知或执行历史打开结果。只读结果视图呈现执行内容、状态、输出与必要错误信息。后续讨论若支持，应创建普通会话，不能把定时授权迁移到人工聊天。

执行前失败也必须通知；按错过策略跳过的执行可以记录历史而不通知。通知发布失败不改变运行结果，不能自动重新执行任务。结果投递与任务重跑是两个独立操作。

## 未读语义

会话列表使用蓝色圆点与“未读消息”可访问名称。通知记录的单调递增 ID 是通知版本；Session 分别保存 notificationVersion 和 readVersion，前者大于后者时显示蓝点。

读取回执携带页面已展示的版本 n，服务端更新为 max(readVersion, min(notificationVersion, n))。这保证阅读期间到达的新结果仍未读。只有内容加载成功、文档可见并且窗口拥有焦点才发送回执；点击导航本身不代表已读。

来源会话与执行会话独立已读：阅读来源摘要清除来源蓝点；阅读结果清除结果蓝点和对应通知中心未读状态。通知中心只按目标会话计算未读数，避免重复计数。普通人工会话保留最终 agent_settled 订阅，按持久化消息 ID 去重。完成时若有连接聚焦该会话，直接跳过，不写通知或去重记录；同一事件在失焦后再次到达时允许正常通知；切会话、失焦、断连时正常通知。焦点随 Conversation 连接同步和清理，不检查渲染或视口。工具中间事件不通知，详情见 [ADR 0041](../adr/0041-result-observation-notifications.md)。

## 离线、重启与清理

Server 使用有界分页补齐 Scheduler 历史，不需要后台常驻模型进程；Server 离线时 Scheduler 可以继续执行。补齐以运行 ID 去重，不能只依赖瞬时 WebSocket 事件。前端定期刷新通知与会话目录，并在恢复焦点时刷新。

归档不删除历史和结果。彻底删除任务应同步清理已登记结果会话及通知引用，保留必要授权审计。用户单独移除结果会话时保留投递去重凭据，防止后续扫描再次创建。来源会话已删除时仍交付结果，但不恢复来源会话。来源提示中的历史链接失效时提供明确的已删除状态。

## API 与边界

- GET /api/notifications：跨工作区分页，每页 20 条，可按 sessionId 查询来源结果链接，返回 hasMore 和未读数。
- POST /api/workspaces/:workspaceId/sessions/:sessionId/read：校验工作区归属与非负整数版本，只确认已观察版本。
- Agent 结果导出：只允许可信控制面访问，必须验证 workspace/task/run 归属与路径边界；浏览器响应不包含本地 Session 文件路径。
- 只读执行会话：激活、订阅 Runtime、执行命令与直接删除 Agent 文件均由后端拒绝；不可仅在前端隐藏 Composer。
