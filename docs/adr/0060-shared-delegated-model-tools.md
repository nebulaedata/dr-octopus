# ADR-0060: 通过共享注册入口和单一名单委派内置工具

## Status

Accepted

## Context

ADR-0057 的子入口只提供知识与记忆读取，主会话已有的 OCR、Embedding 和 Rerank 没有进入子会话。继续逐个复制工具实现会导致 schema、描述、取消与执行逻辑漂移。用户要求对已共享的工具只配置名称即可开放委派。

## Decision

- 保留 required-child-extensions、不可变上下文快照和前后台同一入口，不代理父进程中的工具闭包。
- Knowledge 的 shared-tools.ts 同时注册检索和三个独立模型工具。主会话与子会话复用该入口，分别注入自己的 KnowledgeClient。
- subagent-bridge/contracts.ts 的 CHILD_TOOLS 是唯一可委派名称名单；父快照、子定义筛选和内置 explorer 的 tools 均从它派生。已在共享入口注册的工具，只需在此添加名称即可开放委派。
- 子入口仍注册名单内完整定义以满足 Pi 存在性预检，再按父快照隐藏和拒绝未授权执行。名单外工具不注册。
- OCR、Embedding、Rerank 不受知识模式开关或集合选择限制，但必须存在于父会话活动工具快照，并受子代理自身工具配置限制。知识检索保留集合边界，Memory 保留只读策略。
- 子 KnowledgeClient 保持 `autostart: false`、`globalWrite: false`，并显式获得 `modelAccess: invoke`；独立模型调用可上传 OCR 临时输入，但不获得知识写入、模型配置管理或 daemon 生命周期能力。模型调用资格与知识写权限相互独立，详见 ADR-0063。
- 全新模块仍需提供一次可独立运行的子入口及上下文适配；仅增加名称不会自动把父会话交互、控制能力变成可委派工具。第三方扩展继续使用 Pi 原生资源加载。

## Alternatives

- 为三个模型工具复制子实现：容易发生行为漂移。
- 自动复制全部父扩展：会带入命令、生命周期和不可共享状态。
- 父进程通用工具 RPC：增加取消、并发、父进程退出与后台任务存活的耦合，本次不需要。

## Consequences

现有共享工具的接入成本降为单一名单配置。父活动工具快照仍不等同于通用权限系统完整策略，未新增交互 ask 或文件沙箱继承。后台任务继续使用启动时快照。自定义子代理的显式 tools 白名单仍由其作者维护；已运行的子代理不热更新。

回归覆盖知识模式关闭后的模型工具继承、未授权直接调用和重新激活拒绝，以及前台/后台真实 Pi 子会话中的 OCR 上传、向量化和重排调用。模型服务使用隔离的本地测试端点。
