# ADR-0076：远端智能体通过显式内网/VPN HTTP 接入 Executor

状态：Accepted。日期：2026-10-08。

## 背景

用户确认远端智能体位于可信内网/VPN，使用显式 HTTP 与独立客户端 Bearer 授权连接本机 Executor。Windows-MCP 仍只操作本机；Native Host 与 MCP stdio 仍需连接原有回环 Runtime，不能随外部地址改变或创建第二套执行器。

## 决策

- 默认仅监听 `127.0.0.1`。设置中显式启用后，保存本机的一个数值 IPv4 地址；允许 RFC1918 和 VPN 常用的 `100.64.0.0/10`，不接受 wildcard、DNS、公网或 IPv6 地址。
- 同一 HttpGateway 在回环和指定网卡地址上监听同一端口，共享唯一 Runtime、TaskAuthority、授权、幂等历史、请求/消息预算和会话总上限。增加的是同一服务的网络监听，不是新的 Runtime。
- 回环继续提供 `/mcp` 与 `/browser-bridge`；网络监听仅提供 `/mcp`。每个入口精确检查对应 Host，均拒绝 Origin；角色凭据独立，浏览器凭据不认证 MCP。会话绑定客户端与入口类型，不跨回环/网络入口转移。
- 网络配置在下次完整启动生效，不中断在途动作。任一配置的监听失败，关闭本次监听并报告启动失败，不切换地址或端口、不静默仅本机运行。
- Main/Preload 只提供具名设置与导出接口。Renderer 得到实际监听地址和安全设置，不得到 Bearer 或桥接凭据。远端 HTTP 只有实际网络监听就绪后才可创建新授权并导出配置；本地 HTTP/stdio 继续导出回环 URL。
- 不自动修改防火墙，不自动发现公网、开启端口转发或部署 TLS。明文 HTTP 只用于已选择的可信网络，配置需安全传递；实际跨电脑可达性由专用环境验收。

## 后果与验收

Native Host/stdio 保持原有地址契约和唯一服务所有权。双监听的 TCP 连接各最多 32，MCP 会话总计最多 32、每身份最多 4，MCP 请求并发与消息预算仍全局共享。健康检测依据实际监听与 Runtime 响应，不推断防火墙或远端可达性。

私有设置历史中的地址缺省表示未启用网络；既有端口记录不改写、不删除。新记录总是明确保存地址或 null。启用/禁用需要完整退出和重新打开；禁用不撤销已创建凭据，销毁凭据须明确撤销客户端授权。

测试包括真实本机私有网卡上的 SDK 工具调用、无/错误凭据、错误 Host/Origin、错误角色、会话跨入口/身份、撤销、端口碰撞、重启和退出。跨电脑/VPN、防火墙、实际智能体客户端及干净离线发行另验收；不提升 G4/G5/G6。当前接入见 [Executor](../architecture/executor.md#mcp-接入与等待)，准确验证范围见 [验证矩阵](../architecture/executor-validation.md)。
