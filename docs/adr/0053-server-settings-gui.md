# ADR-0053: Server 设置复用环境配置，由宿主协调重启

## Status

Accepted — 2026-09-18 已实现配置页面、Expose server 开关和宿主内手动重启。用户已确认监听开关、允许远程管理及移除出站代理配置。方案见[主设计](../architecture/settings-server.md)与[实施契约](../architecture/settings-server-contracts.md)。已执行 Windows 自动化验证；其他平台和真实远程/反向代理部署仍需发布前验收。

## Context

2026-09-18 重新评估后开始实施。保留现有决策，补充通用环境存储的锁内检查/提交快照、旧配置诊断、实际生效值比较和跨入口 Origin 拒绝契约；详见实施契约 §1。Expose server 与已有“允许其他设备访问”是同一开关；页面顶部另设手动重启操作。实现完成与验收状态按实际结果更新。

/settings/server 需要图形化管理监听、端口、实例容量和文件日志，并提供重启。ADR-0047 已确定环境配置文件与覆盖优先级；ADR-0044 已确定宿主持有生命周期。Server 启动环境注入已补齐，应直接复用它，避免引入第二份配置。

## Decision

1. 复用 Server environment.json、env-loader 与 revision；结构化表单和环境页面共用短时配置控制队列、校验、安全投影及危险确认，不写仓库 .env。
2. 保存与应用分离，首版保存后由用户显式确认重启，保存绝不自动触发重启。区分 current/next 与启动覆盖，嵌入宿主无法预测时如实显示。
3. 监听开关映射 SERVER_HOST，关闭保留回环访问，开启标为危险。允许远程修改和重启，与其他设置保持一致；不新增仅本机管理限制，CORS 和危险确认不代替认证。
4. 本期删除出站代理及代理排除配置；不新增对应页面、字段、客户端适配或代理验收任务。保留已完成的 Server 环境变量注入机制，不回滚通用环境设置。
5. apps/server 导出通用宿主协调器，CLI Gateway 与独立入口复用。Web 重启在原宿主内重建 runtime，Gateway 保留锁和控制面；复用现有优雅关闭，不增加全应用写入 lease 或自动中断安全判定；停止优先于重启，Server 不依赖 CLI 私有实现，也不调用 process.exit。
6. 重启接受时冻结配置与环境，旧资源完全释放后应用；不在启动前重新读取不同版本文件。失败最多恢复旧运行快照一次，保留用户的新 JSON。操作去重有界保留在宿主内存，进程退出后的结果可为未知。
7. 统一 HTTP 契约增加 server_restart effect，新页面保存返回资源和 mutation metadata；现有环境 PATCH 保留原响应结构，通过 header 扩展危险确认。

## Alternatives considered

- 独立 settings 数据库或新 JSON：会产生两个配置权威，不采用。
- GUI 编辑仓库 .env：生产无需仓库文件，且覆盖层来源不再清晰，不采用。
- 所有配置热更新：首版将监听、日志和会话进程统一放入重启应用边界，降低部分生效的不确定性。
- HTTP 调用 CLI restart 子进程：会自停并争抢 Gateway 锁，采用宿主控制接口。
- 常驻监督进程：能支持完整进程替换，但增加部署与 IPC 成本；当前重建 runtime 即可应用支持重配置的资源。

## Consequences

配置和运行状态可区分，无需迁移持久化数据。代价是重启会中断 Server 所有会话进程，改端口可能需要手动处理访问入口。完整代码升级与重新读取启动 .env 仍由 CLI 或外部进程管理器负责。

本期不涉及 packages/agent 修改。后续如需调整其公共契约，仍须先提出具体改动并取得用户确认。

## Validation

以实施契约的状态机、并发、快照、HTTP 契约及主设计的浏览器矩阵为完成标准。新增配置事务、宿主故障/停止竞态、有界历史、真实 HTTP 响应交接和 CLI Gateway 重启测试；浏览器验证覆盖确认保存、显式重启、模态/独立路由、暗色与窄屏。浏览器业务响应使用隔离 fixture，不能代替真实远程网络验收；未修改 Agent core。
