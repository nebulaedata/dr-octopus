# ADR-0086：同一浏览器扩展内录制与本地智能重放

- 状态：Accepted（第一阶段实施与验证中；编译/重放未实施）
- 日期：2026-10-27

## 背景

现有 `apps/browser-extension` 是 Chrome/Edge WXT/MV3 Native Messaging 桥接，拥有连接管理、有限 Browser 工具与 PageController 页面控制。原始录制设计以独立插件为假设，包含 Popup 管理、DOM/浏览器双通道录制、LLM 编译及 Page Agent 重放，与现有“仅桥接、无 Agent Loop”规则冲突。

用户已确认在同一扩展中新增录制、浮条、事件保存与查看，保留现有桥接；保留扩展本地 AI 重放方向，分阶段交付。用户已于 2026-10-27 明确授权第一阶段代码实施，要求先建 recorder 分支；后续编译/重放阶段仍须另获明确指令。

## 决策

1. 录制是扩展拥有的独立业务，不经 Native Host，不要求 Executor 或模型在线。Popup 保留连接管理，新增录制/工作流命令；Content/SW 复用现有入口。工作流不新增 MCP、聊天或 Side Panel。
2. 编译和本地 Page Agent 重放使用非活动 Extension Agent Host 标签页，纯录制不创建 Host。该技术页可能可见或被关闭，不承诺永久运行；持久检查点与中断状态独立保存。
3. 页面执行复用现有 PageController 公开能力与受控路由，不复制整套官方扩展。Bridge 与本地 run 使用不同且真实的所有者身份，经 SW 共同准入，禁止同页或焦点冲突抢占；停止不等于撤回已发动作。
4. 录制事件和工作流由扩展存储，源端先脱敏、事务提交后 ACK，预算有界，异常退出可出现可见缺口。模型密钥默认仅在受信 Host 内存，不借用 Runtime Bearer 或桥接凭据。
5. Native v3 和跨 Host 白名单保持独立；私有录制消息归扩展。业务不进入 `packages/agent`，不修改共享 shadcn 源组件。现有双浏览器构建、许可和真实验收规则继续适用。

详细范围、状态、准入、预算、文件落点与阶段只维护在[融合设计](../architecture/browser-extension-recorder.md)，本 ADR 不复制执行流程。长期规则见[扩展规范](../../apps/browser-extension/AGENTS.md)，证据见[验证矩阵](../poc/executor-validation.md#浏览器录制与本地重放第一阶段验证中)。

## 替代方案与取舍

| 方案                                             | 评估                                                                             |
| ------------------------------------------------ | -------------------------------------------------------------------------------- |
| 新建独立录制扩展                                 | 隔离简单，但重复安装、身份、权限、内容脚本与发布；不符合保留同一插件入口的目标   |
| 所有编译/重放通过 Executor 与共享 Agent          | 可复用现有模型管理，但使新能力依赖本机服务并扩大跨应用协议与授权范围；本次不采用 |
| 用 Popup 或普通 SW 持有持续 Agent                | 组件生命周期无法代表任务生命周期；不能依赖当前 Native 连接永久保活               |
| 复制官方扩展整套跨 Tab 控制                      | 接入看似直接，但会形成第二套 Controller、注入和资源所有权；只按必要职责参考适配  |
| 同一扩展内独立录制、本地 Host 重放、共同页面准入 | 满足既有功能保留与本地工作流需求；接受技术标签页、独立模型配置和冲突处理成本     |

## 后果与验证

先交付录制/查看，再编译/审阅，再本地重放，最后双目标回归与发布验证。原有安装用户流程在实际功能可用前不提前改写。

需要验证固定 Core/Controller 兼容性、脚本执行禁用、Host 失效、SW/页面恢复、未知在途结果、敏感输入、存储配额及已有 Browser 工具回归。设计接受不代表这些检查已通过；第一阶段已有运行时实现与有限验证，后续阶段仍须用户明确要求实施。
