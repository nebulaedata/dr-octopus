# ADR-0093: 以独立进程内资源统一配置变更登记

日期：2026-11-04。作者：Codex。

## Status

Accepted — 2026-11-04 用户确认实施；独立服务、装配和发布入口迁移已完成，最终验证见 PoC 记录。

## Context

现有 RuntimeConfigChanges 已集中配置版本和订阅，但由 SessionRuntimeCoordinator 创建、公开和关闭。各配置模块通过 sessionRuntime 获取提交能力，导致配置保存与 Agent 运行时的生命周期和接口耦合。

不同配置具有不同提交语义：无变化保存、幂等重放、提交后投影失败、后台认证以及工作区技能都不能通过 HTTP 状态或方法成功统一推断。需要独立管理公共通知机制，同时保留可靠的提交事实来源。

## Decision

采用以下方案，实施以[设计契约](../architecture/configuration-change-service.md)为准：

1. 在现有 Server runtime-config 目录提取 ConfigurationChanges，由独立 Fastify 基础设施插件持有；每个 Server 仅一个版本源。Coordinator 不再创建、公开或关闭它。
2. 各配置模块入口绑定类别并注入窄提交回调，业务写入不依赖 Runtime、路由字符串或推送通道。真实 changed/committed 判断保留在原写入边界。
3. 服务统一维护类别目录、全局和 Workspace 最后变更版本、同步提交发布、订阅隔离及诊断。它不解释配置值、不执行重启、不做通用领域事件总线。
4. Runtime 读取版本并订阅失效；现有 Sessions/SSE 和 Web 手动重启流程保留，外部 DTO 不变。配置提交只提示，不能自动中断任务。
5. 模型监视器继续作为模型变化通知的唯一确认者；Store/认证流程只使其失效，避免重复发布。Jev 现有提交后失败核对保留，不虚构 SDK 提交契约。
6. 不采用 HTTP AOP、成功返回装饰器、全局文件写入拦截或无条件的 save-and-notify 包装器；不新增消息队列、持久事件表或文件监听范围。
7. 所有调用方一次迁移到新所有权；删除旧实现和转发入口，不维持双通知服务。

## Alternatives

| 方案                       | 评估                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 保持 Coordinator 所有权    | 功能可用，但配置模块继续依赖会话运行时，不满足独立维护目标         |
| HTTP 状态/路由 AOP         | 无法准确覆盖 changed、提交后失败、重放与异步认证                   |
| Service 成功后装饰器       | 需要先统一提交结果；当前 SDK/Store 契约不同，隐藏差异会漏报或重复  |
| 集中独立资源与显式提交回调 | 本提案；保留必要触发点，统一版本、作用域和生命周期                 |
| 通用事件总线或独立通知进程 | 当前只有有限配置类别与单一主要消费者，额外运维和投递机制无实际必要 |

## Consequences

- 配置写入与 Runtime 解耦，通知资源能独立测试，新增类别不需要进入 Coordinator 编写发布逻辑。
- 各模块仍需要显式报告实际提交；不能承诺新增一个配置接口就自动获得通知。
- 注入式测试/嵌入入口必须迁移为明确的共享实例；需要新增关闭顺序和实例一致性验证。
- 本服务只保证当前 Server 进程内版本记录与失效投影，不承诺跨进程可靠投递或外部文件自动同步。

本 ADR 仅修订 [ADR-0052](0052-explicit-config-change-session-restart.md) 的服务所有权、类别接入方式和相关生命周期；保留其显式提交、作用域隔离与用户手动重启决定。ADR-0052 的其他产品行为契约继续有效。
