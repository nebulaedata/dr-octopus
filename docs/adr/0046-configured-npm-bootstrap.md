# ADR-0046: 独立配置的 npm 引导包与 pnpm 运行归档

## Status

Accepted — 2026-09-10。用户确认由独立配置文件维护发布契约，并授权实施。

2026-09-15 补充：用户确认下述“依赖安装的网络与非交互策略”，经评估取消地区检测，采用显式源配置与失败诊断。CLI 参数、安装流程、诊断与操作文档已实现；验证范围见下文补充记录。

本决策取代 ADR-0043 的外层目录交付和发布字段修补方式，保留内部原始 workspace、锁文件、补丁与生产过滤安装原则。

## Context

用户需要通过 npm 安装后直接执行 dr-octopus；首次启动询问是否安装运行依赖，也支持 deps install 和启动参数自动安装。直接把开发 workspace 的 package.json 当作 npm 发布清单，会暴露开发脚本和私有 workspace 依赖；全局 npm 目录也不适合作为后续可写运行目录。发布脚本中维护项目路径会使目录迁移变得脆弱。

## Decision

根 release.config.json 是唯一手工维护的发布契约，声明外层 npm 元数据、命令入口、pnpm 精确版本、构建参数、按包名选择的产物目录、运行资源角色及用户缓存相对目录。开发根 package.json 保持 private 并移除 bin。

发布脚本通过 pnpm 发现 workspace 包，按包身份解析配置中的资源，调用现有构建图，复制原始内部安装图与产物。外层 package.json 全量生成，只声明引导入口、精确 files 和 pnpm 依赖。内层 workspace 压缩为 tar.gz，包含原始 pnpm-lock.yaml、pnpm-workspace.yaml、包清单及补丁；npm 无需理解内部 workspace 协议。

构建生成 release-layout.json，记录已解析的路径与归档 SHA-256。CLI 从自身所在位置寻找该索引，不依赖 cwd 或固定仓库深度。开发模式从配置和 workspace glob 获取相同的资源映射。只迁移包目录无需修改脚本；改变产物位置需要更新配置和所属包构建任务；业务公开接口变化仍需代码适配。

运行安装位于 OS 用户主目录内，按归档标识、平台、架构和 Node ABI 隔离。目录使用 24 位哈希前缀缩短 Windows 原生编译路径，实际归档与已解压标记始终使用完整 SHA-256 校验。拒绝链接和越界路径，解压暂存后原子改名。安装器使用外层 npm 包声明的 pnpm，经公开入口定位并核实版本，通过当前 Node 执行，不依赖全局 pnpm。

裸命令和需要运行环境的启动命令在依赖缺失时交互询问，默认拒绝；--install-deps 明确允许自动安装；deps install 始终显式安装。非交互与 JSON 模式不询问。帮助和基础 Gateway 控制不触发安装。通过实际解析和原生模块验证判断依赖是否可用，避免只依赖安装完成标记。使用普通 readline，不接管终端 raw mode。

安装锁隔离并发，已确认退出的安装器可恢复；对当前运行目录执行依赖修改前检查 Gateway 与 Scheduler。使用原始锁文件冻结安装，失败可重试，不修改 Agent 核心。发布组装采用 staging 并保留已有发布目录的占用保护。

## 依赖安装的网络与非交互策略

### 目标与职责

通过独立的安装授权和源选择选项，让普通用户与智能体明确控制运行依赖安装。首期交付 `--yes/-y`、`--registry`、针对性的安装失败诊断，以及对应操作文档。

此策略由 `apps/cli` 的统一依赖安装流程负责，覆盖 `deps install`、裸命令 `dr-octopus` 的首次安装，以及 TUI、Gateway、Scheduler 等需要运行依赖的启动入口。入口传递安装授权与 registry 选项，安装执行和错误诊断共享同一实现，不修改 `packages/agent`。

“静默”指安装流程不等待用户输入，仍保留进度、错误日志和退出码；不改变启动后的 TUI 或其他应用交互。

### 决策依据

不检测 IP 归属地，也不根据语言或时区推断地区。地区不等于下载可达性：企业网络、代理和 VPN 都可能改变实际访问条件；外部归属地服务还增加超时、不可达和维护成本。

npm registry、包 tarball、原生模块二进制和安装脚本可能访问不同域名。换源只解决其中部分问题，不能将所有安装失败归因为中国网络。显式源配置让同一条命令行为可预测，也便于智能体诊断与重试。

### 参数契约

| 参数或入口 | 安装授权 | 镜像选择与交互 |
| --- | --- | --- |
| `--yes` / `-y` | 自动确认依赖安装 | 跳过安装相关询问，不隐含换源 |
| `--install-deps` | 保留现有显式安装授权 | 按配置使用源，不引入新的镜像询问 |
| `--registry <url>` | 单独使用不代表同意安装 | 显式指定本次安装的默认 registry |
| `deps install` | 命令本身即代表同意安装 | 无需额外授权参数；非交互时直接执行，允许同时传 `--yes` |
| 裸命令或隐式安装入口，无安装授权参数 | 交互终端询问是否安装，默认拒绝 | 非交互或 JSON 模式依赖缺失时返回明确错误与安装命令，不自行安装 |

新参数支持裸命令及相关子命令的安装入口。TUI 的 CLI 安装选项在 Agent 参数前解析；`--` 后的参数继续原样交给 Agent，不解释为安装授权。

帮助、版本、Gateway status/stop 等原本不需要安装的命令，即使带有自动确认参数，也不触发安装。已有依赖可用的启动路径直接继续；`deps install` 保留显式执行安装的语义。

### 安装流程与源优先级

1. 按现有规则判断是否需要安装，解析并校验安装选项。
2. 默认源优先级为 CLI `--registry`、安装上下文中已有的 npm/pnpm 有效配置、包管理器内置默认值。未指定 CLI registry 时沿用 pnpm 配置解析，不自行重建配置合并规则。
3. 交互式首次安装确认显示当前源，并提示可以用 `--registry` 指定镜像，默认拒绝安装。显式授权或 `deps install` 直接继续，不增加镜像选择步骤。
4. 非交互与 JSON 模式不读取 stdin；隐式安装缺少授权时返回明确错误，给出 `deps install` 或 `--yes` 使用方式。
5. 在现有安装锁、运行中服务占用检查及冻结锁文件约束下执行 pnpm 安装，完成后继续实际依赖解析与原生模块验证。

`--registry` 使用 pnpm 支持的合法 HTTP(S) registry URL，无效值在安装前失败。它覆盖本次安装的默认源，保留 scoped registry 和按域名绑定的认证配置，不将旧源凭据迁移到新源。已有企业源不得因网络错误被自动替换。

安装确认继续使用普通 readline；Ctrl+C 或 EOF 取消安装并清理监听器。整个流程不查询地区，也不进行额外的安装前联网探测。

### 生效范围与失败处理

CLI 指定的 registry 仅对本次运行依赖安装生效，不写入全局或项目 npm/pnpm 配置、不修改发布锁文件、不保存镜像偏好。它不影响此前的 `npm install -g dr-octopus`，也不承诺覆盖锁文件中的显式 tarball URL 或安装脚本自定义下载地址。

安装进度说明所选源。失败时保留 pnpm 的退出状态和必要诊断，根据明确错误码及阶段信息分类；证据不足时报告未知安装失败，不凭通用非零退出码推测原因。

| 失败类别 | 诊断与建议 |
| --- | --- |
| registry 或包下载的 DNS、连接、超时等网络错误 | 报告可识别的下载阶段和目标，提示检查网络、代理或通过 `--registry` 显式重试 |
| 认证、权限或包不存在 | 检查源、凭据或包信息，不直接推荐公共镜像替换企业源 |
| 原生模块二进制下载失败 | 指明实际下载目标可能独立于 npm registry，换源未必有效 |
| 原生模块编译、生命周期脚本或依赖验证失败 | 保留对应错误，提示检查日志与编译环境，不泛化为换源建议 |

无显式自定义源的公共 npm 下载网络错误可以附上淘宝镜像重试示例；已有显式源时优先提示检查该源。首期不自动换源、不额外编排重试、不在失败后新增询问；pnpm 自身原有网络重试行为保持不变。

诊断与重试示例中的 URL 隐藏凭据及敏感参数，不打印认证 token。JSON 模式沿用既有结构化结果协议，进度与诊断写入 stderr，失败返回非零退出码。

淘宝镜像主要改善 npm 包下载。原生模块仍可能从 GitHub 等站点下载二进制，也可能需要本机编译工具链，因此不能保证所有中国网络安装都成功。首期不自动配置各原生模块的下载镜像，不在失败后自动换源重试；用户根据诊断显式指定源后重试。

### 使用示例

```sh
# 自动确认安装，沿用现有源；完成后显示默认帮助
dr-octopus --yes

# 智能体显式指定镜像，不等待安装输入
dr-octopus deps install --yes --registry https://registry.npmmirror.com

# 安装完成后启动 Gateway
dr-octopus gateway start --yes --registry https://registry.npmmirror.com

# 保留现有安装入口和源配置
dr-octopus gateway start --install-deps

# 显式使用官方源
dr-octopus deps install --yes --registry https://registry.npmjs.org
```

首次安装确认的呈现示例：

```text
需要安装运行依赖。
安装源：https://registry.npmjs.org
可使用 --registry 指定镜像。
是否安装？[y/N]
```

### 后续可选能力

根据真实失败样本再决定是否增加候选源可达性探测，首期不实现。它比地区检测更接近下载问题，但轻量检查也不能证明后续所有资源可下载。

若以后引入，仅在没有显式源时进行短超时、有限并发的协议检查。默认源正常时继续使用；默认源失败而镜像正常时才推荐，不根据一次延迟测量自动选择最快源。

失败后询问是否切换淘宝镜像重试一次，也属于后续可选项，需要独立确认。它只应面向无显式源且可识别的下载网络错误，不能覆盖企业源、掩盖编译错误，或让非交互安装等待输入。

### 验收范围

- 用确定性 fixture 验证 CLI registry、已有配置与默认源的优先级；全局配置、锁文件及 scoped registry/认证配置不被改写。
- 验证合法及非法 registry 参数，失败输出与重试示例不泄露凭据。
- 验证安装确认展示当前源、默认拒绝及 Ctrl+C/EOF 取消，覆盖裸命令和相关启动入口。
- 验证 `--yes`、`-y`、`--install-deps` 和 `deps install` 在非交互与 JSON 模式不读取 stdin；无授权的隐式安装仍失败并给出安装提示。
- 验证参数位置及 TUI `--` 透传边界；帮助、版本、基础控制与依赖已就绪时不安装；所有路径均不依赖归属地服务或额外可达性探测。
- 模拟下载网络错误、认证失败、原生下载/编译失败及未知错误，验证建议与证据匹配，不自动换源或额外重试。
- 验证安装锁、服务占用保护、失败退出码、凭据脱敏和 JSON 输出协议不退化。
- 同步更新 CLI 操作说明和根 `README.md`，运行相关测试、lint、typecheck。真实网络故障仍需依据实际日志区分 registry、tarball 和原生模块下载/编译阶段，不以离线 fixture 代替目标网络验收。

2026-09-15 实施验证：发布 CLI fixture 覆盖根命令与启动入口、非交互安装授权、registry 传递、无效 URL、TUI `--` 边界；新增错误分类、URL/认证脱敏和跨输出分块脱敏测试。真实 pnpm 11.18.0 的隔离离线空依赖安装验证了 `.npmrc` 有效源读取、显式覆盖，以及 scoped registry 配置与规范格式锁文件保持原样。该检查不下载应用完整依赖，不能证明中国网络下所有原生模块都可安装。

CLI 全量测试 44/47 通过；3 项运行目录清理测试因当前环境无法检查 Node 进程命令行而失败，与此前记录一致。

## Consequences

- npm 安装能注册命令，不需要发布私有内部包；依赖和补丁仍以原始 workspace 配置为准。
- 全局 npm 安装目录不承载可变运行依赖；不同发布物和 Node ABI 不共享原生模块。
- 引导包随附 pnpm 会增加 npm 下载体积，首次依赖安装仍需要网络或本地缓存，以及适用的原生编译工具链。
- 新版本使用新的运行目录；旧目录的自动回收不在本次范围内。
- 外层配置与自动路径索引构成明确契约，不能消除业务接口或包构建任务自身的依赖。

## Validation

CLI 的 22 项测试、lint 与 TypeScript 检查通过，全仓构建通过。测试覆盖独立发布清单、包与产物目录迁移、归档完整性、锁竞争与故障恢复，以及首次确认/取消、自动安装参数和 Ctrl+C 清理。Windows 上实际执行 npm pack、npm install 与冻结依赖安装，原生模块检查通过；禁用 registry 后再次启动验证已有依赖不触发安装。Windows MSBuild 对过深路径仍有限制，真实安装验证使用短路径隔离目录；Linux/macOS 仍需在对应系统验收。
