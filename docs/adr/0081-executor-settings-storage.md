# ADR-0081: Executor 正式设置与传输限额

## 状态

Accepted — 2026-10-15。用户确认先规划文档、再实施。本记录先于功能修改落盘，实际验证单独记录。

目录分工、命名与旧路径导入决定已由 [ADR-0083](./0083-executor-project-storage.md) 替代；本文保留原始决定，传输额度规则继续适用。

## 目录与权威来源

正式设置唯一来源为当前用户主目录 `.dr-octopus/executor/settings.json`。传输持久记录也位于该项目目录的受保护子目录。Electron 的 userData、授权、设备身份和传输临时材料继续在 `%APPDATA%/Octopus Executor`，不通过修改 Electron userData 将 Chromium 数据一起搬入项目目录。

传输旧 journal 在新目录不存在时校验并一次性复制，保留原件与原临时材料位置；以后只读写新 journal。记录中的源快照路径不改变，因此未知提交、残留额度和旧任务事实仍按原规则恢复。导入标记存在而正式 journal 丢失时拒绝启动，不回退旧记录。迁移不搬运大文件、不重新执行任务。

AppData 下的设置工作目录保存 before/after 比较、恢复记录及不可回退的初始化事实，不提供另一套配置值。最终替换的私有暂存目录必须与 settings.json 同卷，位于其父目录，成功后删除本次明确拥有的临时文件及空目录；不能依赖 AppData 与用户主目录同卷。失败保留证据，绝不静默用历史记录覆盖正式设置。记录没有文件内容理解或通用 diff 服务职责。

已有正式 settings.json 时只读取它。首次转用新位置且正式文件不存在时，允许一次性校验并导入旧有编号设置记录，保留原件；不双写、不覆盖已经存在的新设置。损坏数据拒绝启动。设备身份初始化标记随正式设置保存，设备 ID/名称仍由既有身份模块拥有。

生产正式目录固定在用户主目录。显式 --user-data-dir 和测试模式使用隔离目录内的 project/settings.json，避免多实例或测试写入用户正式配置；默认 AppData 不变。设置文件仍受当前 Windows 用户私有 ACL 保护。

## 可配置传输限制

设置中新增文件传输分组，以下数值使用 MiB 表达，持久化为明确带单位的字段：

| 字段                | 默认值 | 范围及语义                                                                        |
| ------------------- | ------ | --------------------------------------------------------------------------------- |
| uploadLimitMiB      | 2048   | 1–2048，智能体 → 执行体单文件上限                                                 |
| downloadLimitMiB    | 2048   | 1–2048，执行体 → 智能体单文件上限                                                 |
| temporaryQuotaMiB   | 8192   | 1–1048576，执行体所有传输快照、临时材料及残留合计额度；不得小于任一方向单文件上限 |
| minimumFreeSpaceMiB | 512    | 0–1048576，每个实际写入卷预留空间                                                 |

当前实现只支持 2 GiB 文件，配置不得突破协议与原生能力上限。零字节文件继续支持。分块 4 MiB、并发、重试及任务 30 分钟期限不开放配置。

执行体设置只管理执行体磁盘配额和源/目标访问。智能体侧客户端保留独立本地额度，不因执行体额度变大而自动放宽。执行体必须在传输创建/源检查、额度准入和磁盘空间检查实际应用设置；不是仅增加表单字段。runtime_status 提供本次启动生效的限制，方便调用方判断；传输创建返回明确超限错误。

## 生效与一致性

设置通过既有 IPC 校验、持久化并返回；主题和窗口行为保持现有效果，传输参数与网络设置需完整重启。Runtime 持有启动时校验过的不可变快照；保存后显示待重启，不改变在途任务。降低配额不会删除旧材料；启动后旧残留继续计入，新准入按新额度拒绝。

设置保存使用私有暂存、原生检查与替换。结果不明时返回失败并保留 before/after 材料，禁止自动重放。正式文件可明确验证为保存前或保存后内容时，重启只解释事实；第三种内容或缺失且无法确认时拒绝初始化默认值。删除只针对本次已知临时材料，不递归清理未知内容。

## 实施范围与验证

修改 Main 设置存储、Runtime 启动契约、传输准入、设置 UI 与文档；不修改 Agent Core 或共享 UI 原语。重点测试新目录与隔离路径、旧记录首次导入且保留、正式文件优先、损坏/冲突拒绝、重复保存及身份标记、两方向超限/额度/空间校验、保存与重启生效、UI 输入校验与待重启提示。先构建，再运行聚焦测试和相关 test/lint/typecheck；界面使用隔离 Electron 实例验证。
