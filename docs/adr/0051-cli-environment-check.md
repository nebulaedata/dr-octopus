# ADR-0051: CLI 持有跨平台基础环境检测与分级报告

## Status

Proposed — 2026-09-13。设计先行，未实现。首期真实验证范围按用户要求限定为当前 Windows 开发机，其他平台没有环境时不阻塞交付。

## Context

智能体需要 Git、Python 3 和可运行的原生模块。现有 doctor 混合系统工具、发布依赖与服务状态，无法在安装前清楚区分必需能力和建议的源码构建环境。

仓库当前 better-sqlite3 13.0.3 包含预编译资源，不能将缺少 Visual Studio Build Tools 等同于 SQLite 不可运行。平台安装产品名称也不能代替对实际工具、SDK 和架构的检测。

## Decision

1. 在 apps/cli 增加独立、只读、默认离线的 `env check` 命令，不依赖内部运行依赖，不修改 Agent 核心。
2. Node、Git、Python 3 为必需项；平台 C/C++ 工具链及 pip/venv 为建议项。默认只有必需项不通过影响就绪状态，strict 模式同时要求建议项通过。
3. 通过公共命令执行接口和平台适配器发现实际能力；发现失败使用 unknown，不误报未安装或通过。只展示平台对应的安装指引，不自动修改系统。
4. 系统前置检查与安装后原生模块执行验证分离。SQLite 运行测试留在 doctor/依赖验证；有预编译模块可运行时不强制安装编译工具。
5. 独立命令先交付，之后复用到 doctor 和安装/启动入口，避免重复实现判断规则。
6. 首期在 Windows 本机做真实验证，三平台判断逻辑用确定性测试覆盖。没有 macOS/Linux 条件时明确记录未实测，不要求新增 CI 或设备。

详细命令、数据模型、平台规则、阶段和验收见[设计文档](../architecture/cli-environment-check.md)。

## Alternatives

- 只扩展原 doctor：复用入口容易，但基础环境与业务发布诊断继续混合，不利于明确首次安装前的检查边界。
- 所有平台强制安装编译工具链：规则简单，却会阻塞本来可以使用预编译模块的环境，增加安装负担。
- 仅查询安装包名称或 PATH：实现简单，无法可靠识别 Windows 非 PATH 编译器、SDK 缺失与失效 Python 别名。
- 等三平台真实 CI 全部就绪才交付：覆盖更完整，但不符合当前 Windows 开发环境及首期交付约束。

## Consequences

基础检查可在首次安装之前运行，报告可以区分阻塞和建议问题，并供多个 CLI 入口复用。平台探针需要维护组件发现逻辑与安装指引；发现前置条件齐全也不能保证任意源码构建成功。

macOS/Linux 首期只有模拟验证时仍存在真实命令行为差异风险，交付说明必须保留这一限制，后续有条件再补测试。没有真实环境不妨碍交付设计覆盖的代码，但不能据此声称对应平台已通过实际验收。

## Validation

本 ADR 尚无实现验证结果。实施时必须完成 Windows 本机真实检测、CLI 范围检查、确定性失败场景测试，并单独记录原生模块冒烟结果与其他平台暂缓项。
