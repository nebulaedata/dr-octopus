# ADR-0068：指令完成与输出展示分离

## 状态

Accepted。

## 问题与决策

Pi 扩展指令可以发送通知、自定义消息，也可以没有任何输出；指令还可能启动模型回合。业务 `customType`、通知数量与文本不能证明指令完成。通道层不维护 `/memory` 等业务指令名单。

固定版本 Pi 的 `prompt` 响应在普通提示词预检成功后发送，在扩展指令 handler 返回后发送。因此成功 ACK 只保证接受或处理，不能单独证明 Agent 已完成。

斜杠 `agent.prompt` 获得成功响应后，Channel 通过 Sessions 的已有能力，对同一个 runtimeId/epoch 执行一次 `get_state`。只有 `isStreaming === false`、`isCompacting === false`、`pendingMessageCount === 0` 同时成立，才在 `command.ack.completion` 中发布该请求的完成时间与运行时版本。首条 HTTP 投递使用同一确认逻辑，并将确认广播给该会话的订阅者。

普通提示词、steer/follow-up 保持原有 Agent 生命周期。会启动模型的斜杠指令、模板展开或存在其他运行中工作时，ACK 不含完成标记，继续由 Agent 事件收尾。确认的是响应之后观察到的空闲状态，不承诺未来不会有独立后台任务启动。

状态查询失败、响应不完整、运行时已替换时，不报告完成，也不能把已经接受的指令误报为拒绝并触发重发。保留原有运行时故障和快照恢复路径；不新增轮询或业务补偿分支。

`extension.ui.response` 是等待中的指令的输入，必须绕过该会话的指令串行队列，否则 handler 等待用户回复、回复等待 handler 完成会形成死锁。回复继续经过订阅、运行时版本、待处理 UI 请求与幂等校验。

## 前端契约

- 通知与自定义消息只负责展示，不消耗待完成请求，不结束乐观回合。
- 收到完成标记先校验当前订阅的 runtimeId/epoch，再释放该请求的订阅保留。
- Store 按 requestId 找到对应回合，结束该回合并移除对应待确认项；重复确认幂等。
- 旧运行时确认不能修改新投影；旧请求确认不能结束较新的回合，也不能把正在运行的 Agent 强制设为空闲。
- 没有完成标记的 ACK 只记录接受，不提前清除乐观消息的同步保护。扩展启动模型但没有普通 user 消息事件时，由最终 `agent_settled` 清除已接受请求的待确认状态；尚未接受的新请求不被旧回合收尾清除。

## 代价与验证

每次斜杠 prompt 增加一次轻量 RPC 状态查询，换取与业务输出无关的完成确认；无需修改 Agent 或各扩展的实现。

回归覆盖通知、自定义消息、无输出、handler 尚未返回、模型生成、压缩、排队、查询失败、重复请求、首条消息投递、旧运行时确认及新旧回合并存。业务成功与失败内容仍由扩展原样展示；这里的完成标记表示处理已经结束，不替代业务结果。
