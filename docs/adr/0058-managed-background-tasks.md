# ADR-0058: 通过受管后台任务工具管理长期进程

## Status

Accepted（阶段 B）— 2026-09-17。主会话受管任务已实施；平台实测与剩余边界见实施契约。

## Context

Shell 工具通过 nohup 与后台操作符启动的进程可能在调用结束后继续运行。当前 Server 停止链路管理主 Agent 与已登记子代理，不拥有这些普通后台进程。仅增加系统提示词不能建立进程所有权，也不能证明用户点击停止后进程已经退出。

## Decision

1. 新增 background_task Extension/Tool，提供 start、list、status、logs、wait、stop；管理器绑定可信会话身份和 runtime generation，输出有界日志与版本化状态。
2. Server 在现有停止租约内协调主循环、子代理和后台任务，通过非模型控制入口建立启动屏障，并等待实际停止证据。ACK 或 UI 卡片消失不能作为证据。
3. 正常回答结束保留后台任务；用户停止清理当前 generation 的全部受管任务；会话销毁执行幂等清理。取消读取/等待不等于停止进程。
4. 追加提示词并拦截明显脱管写法，启动权限复用 Shell 策略。这些约束属于防误用，不作为任意代码无法逃逸的保证。
5. 分平台声明进程回收能力。强逃逸约束必须覆盖普通 Shell 和子代理，并使用适当的平台容器/监督机制，不能靠根 PID 或进程组夸大保证。
6. 用户确认实施后，在共享 CLI/RPC 组合根装配宿主无关的内置扩展；进程管理实现在 packages/agent，Server/Web 保留各自编排与展示职责。第一阶段不扩张现有子代理只读工具 bridge。

## Alternatives

- 只追加提示词：实现简单，但没有所有权、日志与可验证清理。
- 停止时扫描系统进程树：父进程消失后归属不可靠，存在 PID 复用和误杀风险。
- 每次停止直接杀整个 Pi 运行时：损害会话可用性，也不能保证已脱离的后代退出。
- 第一阶段全面引入隔离容器：可提供更强约束，但跨平台部署与权限成本高；保留为明确的后续阶段。

## Consequences

长期任务有统一管理入口，停止语义可测试、故障可见。代价是额外的进程状态机、平台适配、停止协议和资源预算。首期仅承诺受管主会话任务的已验证能力，不覆盖任意脱管脚本、子代理 Shell 或 POSIX 管理器强杀后的清理。

详细协议、阶段与验收见[受管后台进程设计](../architecture/background-tasks.md)和[阶段 B 实施契约](../architecture/background-tasks-implementation.md)。已验证 Pi 0.85.1 与 Windows x64；POSIX/arm64 实机验证仍是跨平台发布前置条件。
